# ADR-0001: 6개 역할 기반 AI Agent 아키텍처

- 상태: 채택
- 결정일: 2026-08-31

## 맥락

기존 프로젝트에는 QA, 입력 보조, 에러 검토, 차트 분석, 정성정보 유도, fallback의 역할 구상이 있다. 3주 MVP에서 일부 Agent만 남길지, 여섯 역할을 유지할지 결정해야 했다.

## 결정

3주 MVP와 이후 운영에서 다음 6개 Agent 역할을 유지한다.

1. QA
2. 입력 보조
3. 에러 검토
4. 차트 분석
5. 정성정보 유도
6. fallback

모든 Agent는 공통 대화 상태, 라우터, 관측, 보안, 평가 기반을 재사용한다. 각 역할의 경계는 [`AI Agent 요구사항`](../requirements/ai-agent.md)과 [`AI 시스템 명세`](../ai/specification.md)가 정의한다.

에러 검토의 유효성 판정은 결정론적 코드 검증기가 담당하고 LLM은 설명을 맡는다. 차트 분석은 구조화된 원본 수치와 계산 결과만 해석하며 화면 이미지나 누락 데이터를 추측하지 않는다.

`basic-info`, `financial-mindset`, `financial-assets`를 먼저 연동하는 것은 공통 계약을 세 가지 대표 데이터 형태로 검증하기 위한 구현 순서다. 최종 기능 범위를 세 단계로 제한하지 않는다.

## 고려한 대안

### QA·입력 보조·정성정보 유도·fallback만 MVP에 포함

공통 기반 완성 가능성은 높지만 기존 기획의 에러 검토·차트 분석 학습 목표와 서비스 흐름을 MVP에서 검증하지 못한다.

### 단일 범용 Agent

구현 파일 수는 줄지만 도구 권한, 평가 기준, 실패 처리, 프롬프트 책임이 섞여 금융 서비스의 감사와 안전 검증이 어려워진다.

## 결과

- 라우팅과 Agent별 평가셋이 필수다.
- 여섯 역할을 각각 거대한 독립 시스템으로 만들지 않고 공통 도구·상태·검증기를 재사용해야 한다.
- 3주 안에는 각 Agent의 명확한 MVP 책임과 대표 성공·실패 경로를 완성하고, 플랫폼급 보안·가명처리·자산배분 운영은 후속 범위로 둔다.
