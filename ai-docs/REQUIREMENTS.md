# 프로젝트 요구사항

상태: **AI Agent 요구사항 합의됨 — 제품 전체 요구사항은 추가 합의 필요**

`project_plan.md`와 기존 구현은 요구사항을 논의하기 위한 참고 자료이며, 이 문서에 채택된 내용만 현재 프로젝트 범위로 본다.

## 1. 문제

프로젝트 전체가 해결할 사용자 문제는 추가 합의가 필요하다.

AI 영역에서는 기존 은퇴 설계 흐름의 사용자 메시지, 현재 화면, 저장된 재무 정보, 전문 문서를 함께 이해하고도 안전하게 화면과 상호작용하는 Agent가 필요하다. 현재 구현은 Agent 골격은 있으나 대화 문맥, 실제 단계 라우팅, 인터페이스 계약, 운영 RAG, MCP·Function Calling, 평가와 보안 통제가 연결되지 않았다.

## 2. 목표와 성공 지표

### 2.1 서비스 목표

프로젝트 요구사항에 맞게 AI Agent가 정상 작동한다.

- Agent가 같은 상담 세션의 대화 컨텍스트를 적절히 참고해 답변한다.
- Agent가 사용자 의도를 파악해 현재 화면과 상호작용한다.
- Agent가 검토된 문서, RAG, MCP, Function Calling을 근거로 전문성 있는 답변을 제공한다.
- 금융 데이터 수정과 부작용이 있는 행동은 사용자의 명시적 승인 전에는 반영하지 않는다.

### 2.2 역량 취득 목표

1. **AI Agent 구현·운영**
   - AX 업무 지표 확보와 성과 측정
   - RAG 평가 지표 산출
   - LLM 기반 자산배분 모델과 데이터 파이프라인 리서치·운영 경험
2. **AI 아키텍트**
   - MCP 서버 설계·운용
   - FastAPI 기반 AI 서버 운용
3. **보안**
   - 금융 데이터 특성과 보안 요구사항 이해
   - 가명처리·적정성 검토·리포팅 흐름 설계 경험
   - AI 공격 시나리오와 모의 공격 수행
   - Agent 취약점과 가드레일 우회 가능성 검증
   - Zero Trust 원칙 기반 AI 서비스 아키텍처 설계·핵심 통제 검증
   - 프로젝트 수준 AI 보안 정책 v0.1 제정
4. **평가 기반 개발·LLMOps**
   - 같은 평가셋으로 모델·프롬프트·검색 설정을 비교하고 회귀를 차단
   - 모델·프롬프트·데이터·인덱스 버전과 결과 재현성 확보
   - 비용·지연·성공률 SLO와 rollback 기준 운영
5. **금융 AI 거버넌스**
   - Human-in-the-loop 승인 경계와 모델 리스크 관리
   - 금융 지식의 출처·기준일·검토자·폐기 기준 관리

세부 성공 지표와 인수 조건은 [`requirements/ai-agent.md`](requirements/ai-agent.md)를 따른다.

## 3. 사용자

제품 전체 사용자는 추가 합의가 필요하다. AI Agent의 현재 대상은 은퇴 설계 상담 세션에서 질문하고 재무 정보를 입력·검토하는 사용자다.

## 4. 범위

### 포함

- QA, 입력 보조, 에러 검토, 차트 분석, 정성정보 유도, fallback의 6개 Agent
- 세션별 멀티턴 대화 문맥과 사용자 의도 라우팅
- 구조화된 화면 변경 제안과 사용자 승인
- 출처·기준일·버전을 가진 금융 지식 RAG와 재현 가능한 평가
- 최소 3개의 안전한 MCP·Function Calling 도구
- Agent 운영·AX·비용·지연·품질 지표
- 프로젝트 수준 가명처리·공격 검증·Zero Trust 핵심 통제·AI 보안 정책 v0.1
- 결정론적 계산을 중심으로 한 LLM 자산배분 연구 스파이크

### 3주 제외 범위

다음 항목은 3주 MVP에서 운영급 완성을 목표로 하지 않고 후속 로드맵으로 분리한다.

- 분산 가명처리 플랫폼 전체 구축
- 완전한 Zero Trust 인프라와 독립 침투 검증
- 조직 전체에 적용되는 AI 보안 표준·정책
- 실제 투자 의사결정이나 투자 실행에 사용하는 LLM 자산배분 모델
- 검토되지 않은 금융상품 추천과 수익 보장 표현

3주 안에는 AI 전송·trace 대상 필드의 가명처리 MVP, 프로젝트 보안 정책 v0.1, 핵심 공격 시나리오, 서비스 인증·최소 권한·감사 지점을 완료선으로 삼는다.

## 6. 비기능 요구사항

- 보안·개인정보 기준은 [`security/ai-security-policy.md`](security/ai-security-policy.md)를 따른다.
- 모델·프롬프트·RAG·도구 변경은 동일 평가셋으로 회귀를 검사할 수 있어야 한다.
- Agent route, 성공·실패, 지연, 토큰·비용, 검색, 도구 호출, 사용자 승인 결과를 관측할 수 있어야 한다.
- 세션 간 대화와 금융 데이터가 섞이지 않아야 한다.
- 외부 서비스·LLM·callback 실패를 사용자에게 성공으로 표시하지 않아야 한다.

## 7. 용어

- **AX**: AI Transformation. AI 도입으로 업무 시간·완료율·품질이 얼마나 개선됐는지 측정하는 관점.
- **입력 보조**: 사용자 발화를 폼 변경 제안으로 구조화하는 Agent. 직접 저장하지 않는다.
- **에러 검토**: 코드 검증 결과를 바탕으로 오류 이유와 안전한 수정 방법을 설명하는 Agent.
- **MCP**: Model Context Protocol. Agent가 외부 도구·데이터를 명시적 계약으로 호출하는 방식.
- **Function Calling**: LLM이 허용된 함수의 구조화된 인자를 생성하도록 하는 호출 방식.
- **가명처리**: 추가 정보 없이는 개인을 식별하기 어렵도록 식별자를 대체하거나 변환하는 처리.

## 8. 열린 결정

- 운영 LLM·Embedding provider와 버전
- 운영 RAG에 채택할 금융 문서와 갱신 주기
- 1차 baseline 측정 후 확정할 품질·지연·비용 임계값
