# What-if 경계 조건 검증 기록

상태: **4번 확대 경계 검증 완료.** 2026-09-08, Miniforge `retirewise-ai`의
Python 3.13.15에서 기존 251개 + 신규 25개 = **전체 276개 테스트**가 통과했다.
4번에서는 계산 규칙·런타임 코드·의존성을 변경하지 않았다. 후속 5번
[전용 샘플 CLI](what-if-samples.md)도 완료했으며 신규 24개를 포함한 현재 전체는 300개다.
운영 성능·실제 데이터·서비스 연결은 이번 검증에 포함하지 않는다.

구현과 호출 규격은 [비교 계산 가이드](what-if-engine.md), 판정·차이의 의미는
[계산 규칙](what-if-rules.md), 변경값 검증은 [시나리오 생성 가이드](what-if-scenarios.md)를 따른다.
모든 금액·수익률은 합성 테스트 입력이며 시장 전망이나 권장 가정이 아니다.

## 1. 추가한 자동 테스트

[`test_what_if_edges.py`](../tests/test_what_if_edges.py)의 25개 테스트 메서드다.
조합별 `subTest`는 메서드 개수에 중복 합산하지 않는다. 기존 What-if 생성 38개·
비교 32개를 포함하면 What-if 전용은 95개이며 나머지 181개는 기존 모듈 회귀 테스트다.

| 그룹 | 개수 | 확인 내용 |
|---|---:|---|
| `WhatIfReferenceEdgeTests` | 4 | 독립 Decimal 검산, 생성 경로 대조, 변동성 0, 최대 기간·변경안 수 |
| `WhatIfScheduleEdgeTests` | 5 | 18/100세 1년 계산, 마지막 생활비 일정 오류 선검증, 이미 은퇴한 경우의 변경 제한, 비활성 큰 금액, 첫/마지막 나이 고갈 |
| `WhatIfIndependenceEdgeTests` | 5 | 경로 순서·안 추가, 경로 복제, 금액 배율, 동시 호출, 실패 후 재현성과 전역 난수 상태 |
| `WhatIfNumericEdgeTests` | 10 | 극소 음수·회복·수익률 하한, 유한 차이, 실제 overflow, 늦은 경로 오류, 생성 실패·재추출 금지·입력값 비노출 |
| `WhatIfCapacityEdgeTests` | 1 | 100,000개 경로·1년·2개 변경안의 실제 비교·집계 |

일정·원본 보존·공통 경로의 기본 계약은 기존
[`test_what_if.py`](../tests/test_what_if.py),
[`test_what_if_engine.py`](../tests/test_what_if_engine.py)와 함께 검증한다.
기존 테스트를 실행한 것만으로 신규 경계 검증을 대신하지 않았다.

## 2. 독립 검산 방법

기존 몬테카를로 경계 테스트의
[`reference_batch`·`reference_percentiles`](../tests/test_monte_carlo_edges.py)를 재사용한다.
이 참조 계산은 **80자리 Decimal**로 연간 현금흐름, 최초 음수 잔액, 최종 부족액과
type 7 분위수를 계산하며 운영 현금흐름·분위수 함수를 호출하지 않는다.
기대 변경 프로필도 운영 `create_what_if_profile`을 호출하지 않고, 기준 프로필에
명시적 덮어쓰기 값을 직접 적용해 구성한다. 실제 검증 대상은 공개 What-if 계산 함수다.

- 직접 경로: 은퇴 전·이미 은퇴·종료 나이 은퇴 3개 일정 × 물가 `-0.02/0/0.03`
  × 경로 수 `1/2/17` × 시드 `0/97` = **54개 배치**, 각각 변경안 5개.
  경로는 별도의 로컬 RNG로 유한한 이진 분수 수익률 후보에서 선택한다.
- 생성 경로: 같은 3개 일정 × `(평균, 변동성)` `(-0.2, 0.1)/(0.05, 0.2)`
  × 시드 `0/97` = **12개 배치**, 각각 19개 경로·변경안 5개.
  참조 계산에 전달할 경로는 기존 생성기로 별도 재생성한다. 이 검사는 생성된 경로의
  소비·현금흐름·차이 계산 검산이지, 수익률 분포 자체의 독립 검증은 아니다.
- 변동성 0: 3개 일정 × 평균 `-0.25/0/0.05` × 물가 `0/0.02`
  × 경로 수 `1/13` × 시드 `0/(2**256+1)` = **72개 배치**, 각각 변경안 5개.
  난수 생성이 없고 기존 고정 현금흐름 엔진의 잔액·부족액 차이와 정확히 일치함을 확인한다.

각 안의 나이별 잔액 분위수, 최초 고갈 개수, 성공·고갈 개수, 최종 부족액 분위수와
기준 대비 차이를 대조한다. 변경 없음·적립 0·생활비 0·전체 일정 교체·조기/지연 은퇴·
연금 개시/종료·중첩 연금·물가의 현재 나이 기준 누적을 포함한다.

개수·나이 정렬은 정확히 비교한다. Decimal 참조와 float 금액의 비교 허용치는
상대 `1e-10`, 절대 `1e-7` KRW다. pp 차이는 개수 차이의 `Fraction / N × 100`과
절대 `1e-12` pp 범위에서 대조한다. **이는 테스트의 수치 비교 허용치이며, 고갈 판정에
epsilon을 도입하거나 잔액을 0으로 반올림한다는 의미가 아니다.** 극소 음수 고갈은
별도 개수·양수 부족액 단언으로 확인한다. 유한 극값·subnormal 차이는 정확한
`Fraction` 뺄셈을 float로 변환한 기대값과 비교한다.

## 3. 경계에서 유지되는 의미

- 계산 잔액 0은 고갈이 아니고 아주 작은 음수도 고갈이다. 이후 잔액이 회복되어도
  최초 고갈과 실패 이력은 남는다. 음수 잔액에 수익·대출 이자를 붙이지 않는다.
- 이미 은퇴한 나이는 다시 쓰지 않는다. 비활성 적립·생활비·연금 금액은 계산하지 않고,
  생활비 0은 불필요한 물가 거듭제곱을 건너뛴다. 반면 **비활성 생활비 구간의 중첩도
  입력 오류**이므로 무시하지 않는다.
- 경로 순서 변경·독립 변경안 추가는 기존 비교에 영향을 주지 않는다. 금액을 모두 8배로
  바꾼 합성 입력에서는 고갈 개수·pp가 유지되고 금액 차이도 8배다.
- 동일 경로를 2배로 복제하면 개수는 2배이고 확률은 유지되지만, type 7의 표본 수에 따른
  보간 위치가 달라져 **분위수와 분위수 차이까지 반드시 같지는 않다**.
- 실제 3경로 계산에서 최종 잔액의 `P10/P50/P90` 차이가 `-72/-120/-168` KRW인
  사례를 검증한다. 크기순으로 정렬하거나 경로별 차이의 분위수 `-168/-120/-72`로
  바꾸면 의미가 달라진다. 부족액 차이도 별도 집계이며 잔액 차이를 단순히 반전하지 않는다.
- 같은 입력·시드의 동시 호출 결과가 순차 호출과 같고 전역 `random` 상태를 바꾸지 않는다.
  실패한 호출이나 호출 사이의 외부 난수 사용도 다음 실행의 재현성에 영향을 주지 않는다.
  Python 버전·플랫폼 간 비트 단위 재현성을 보장하는 검사는 아니다.

## 4. 오류·수치 범위

마지막 10번째 변경안의 빈 일정·누락·중첩·조기 은퇴의 생활비 미보장을 두 공개 입구에서
검사한다. 변경안 검증 실패 시 경로 검증/생성이나 기준안 계산을 시작하지 않는다.
마지막 경로의 마지막 수익률에 거대한 정수를 넣어도 전체 입력 선검증으로 거부하며
오류에 원본 금액을 노출하지 않는다.

실제 현금흐름 계산으로 `annual_expenses`, `inflation_factor`, `expenses`,
`investment_return`, `balance_after_savings` 오류를 발생시킨다. 기준안·첫 변경안은
정상이어도 중간 변경안이 실패하면 후속 안을 실행하거나 부분 결과를 반환하지 않는다.
마지막 경로에서만 실패하는 경우도 `scenario_index/path_index/age`가 보존된다.

기준·변경안을 각각 실행하면 유한하지만 최종 잔액 차이가 float 범위를 넘는 사례도
**양방향 실제 계산**으로 검증한다. 월 생활비 `10**307`원과 0원, 기초 자산 `10**308`원,
2년·수익률/물가 0인 합성 경계 입력이다. 차이 생성 시 `comparison.asset_deltas.p10`
오류로 중단하며 이것을 시장 사례로 해석하지 않는다.

극소 비영 변동성이 표현되지 않는 경우는 실제 모수 변환으로 검사한다. 마지막 난수
추출의 NaN·너무 큰 양/음 충격은 RNG에만 주입해 재추출 없이 시장 단계에서 실패함을
확인한다. 유한 극값·subnormal의 직접 결과 모델 구성은 출력 계약 검사용이며 실제
공통 경로 계산이라는 주장은 하지 않는다. 기존 3번의 집계 오류 주입 테스트도 유지한다.

명시적 수익률의 오류 위치도 기존 몬테카를로 계약을 따른다. `r <= -1` 오류는
`annual_return_paths[경로]`, 비유한 값·타입/변환 오류는
`annual_return_paths[경로][연도]`를 가리킨다. 런타임 오류 처리 방식은 변경하지 않았다.

## 5. 상한 검사의 범위

- **최대 기간·변경안 수:** 18~120세 103년, 변경안 10개, 경로 3개를 실제 실행하고
  독립 Decimal 결과와 대조한다.
- **최대 경로 수:** 100,000개 경로, 1년, 변경안 2개를 실제 실행한다. 기준 성공
  75,000개에서 각 안이 100,000개로 바뀌는 `+25pp`, 최초 고갈 개수 `-25,000`,
  잔액·부족액 분위수와 차이를 손계산 기대값으로 확인한다.

**100,000경로 × 103년 × 10개 변경안의 동시 최대 설정은 실행하지 않았다.**
독립적인 입력 상한 검증이지 운영 자원 한도·처리량·응답시간 보장은 아니다.
성능 계측, timeout·취소·서비스 부하, 시장 가정 적합성·통계적 신뢰구간, 최적화와
BE/FE·Agent·컨텍스트·실제 입력 adapter 연결은 후속 작업이다.

## 6. 재실행

저장소 루트에서 실행한다. DB·네트워크·API key나 추가 패키지가 필요 없다.

```bash
conda run -n retirewise-ai python -B -m unittest discover -s backend-pjt/packages/retirement_simulation/tests -q
conda run -n retirewise-ai python -S -B -m unittest discover -s backend-pjt/packages/retirement_simulation/tests -q
conda run -n retirewise-ai python -S -B -m unittest discover -s backend-pjt/packages/retirement_simulation/tests -p test_what_if_edges.py -v
```

일반·`-S` 전체 276개, 신규 경계 25개와 전체 메서드를 역순으로 실행한 276개가
통과했다. 역순 실행은 테스트 간 난수·상태 오염을 추가 확인하기 위한 것이다.
아래 명령으로 동일하게 재실행할 수 있다.

```bash
conda run --no-capture-output -n retirewise-ai python -S -B - <<'PY'
import sys
import unittest

def cases(node):
    for item in node:
        if isinstance(item, unittest.TestSuite):
            yield from cases(item)
        else:
            yield item

suite = unittest.defaultTestLoader.discover('backend-pjt/packages/retirement_simulation/tests')
result = unittest.TextTestRunner(verbosity=1).run(
    unittest.TestSuite(reversed(list(cases(suite))))
)
sys.exit(not result.wasSuccessful())
PY
```

4번 이후 진행한 **5번 합성 입력 What-if 전용 CLI·사용 가이드**는
[샘플 가이드](what-if-samples.md)에 기록한다. 4번 경계 검증에서는 기존
현금흐름/몬테카를로 CLI와 타 팀원 코드를 변경하지 않았다.
