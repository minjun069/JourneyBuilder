# P12 자산배분 비제품 연구

상태: **문헌·설계 조사 완료 — 제품 미채택**

기준일: **2026-09-05**

## 1. 목적과 결론

이 연구의 목적은 자산배분 기능을 구현하는 것이 아니라 재무 진단과 재무 설계의
경계를 확인하고, 자산배분 방법론을 제품에 연결할 때 생기는 데이터·평가·운영
위험을 기록하는 것이다.

현재 AI-001의 사용자 기능은 재무 정보 입력·검토와 재무 진단까지다. 기존 고객
snapshot과 이미 합의된 결정론적 산식으로 생성한 자산 현황, 현금 흐름, 재무
지표, 은퇴 준비도·부족액·필요 저축액을 표시하고 설명할 수 있다. 개인별 목표
자산배분 비중, 금융상품 구성, 매매·리밸런싱 또는 실행 계획을 만들거나 최적화해
제시하는 재무 설계는 포함하지 않는다.

따라서 P12는 다음 결론을 D10에 전달한다.

- 자산배분 계산·추천 기능을 현재 제품에 추가하지 않는다.
- 자산배분용 Function Calling 도구, Agent, graph 노드, 화면 계약을 추가하지 않는다.
- optimizer, backtest, 시장 데이터 수집·적재 코드를 구현하지 않는다.
- 아래 방법론 비교는 향후 논의를 위한 조사이며 채택 결정이 아니다.
- 범위를 확장하려면 별도 요구사항과 도메인·보안·계약 검토가 먼저 필요하다.

이 경계는 이 문서의 범위 정의와 현재 제품 코드·계약 검사를 함께 기준으로 삼는다.
범위를 확장하려면 별도 요구사항 합의와 도메인·보안·계약 검토를 선행한다.

## 2. 진단과 설계의 구분

| 구분 | 입력 | 결과 | 현재 제품 판정 |
|---|---|---|---|
| 재무 진단 | 현재 고객 snapshot, 합의된 진단 산식과 가정 | 현재 상태, 지표, 격차, 기존 계산 결과의 설명 | 포함 |
| 재무 설계 | 진단 결과, 투자 성향·제약, 시장 가정과 상품 정보 | 목표 비중, 상품 구성, 매매·리밸런싱·실행 계획 | 제외 |
| P12 연구 | 공개 문헌, 현재 계약과 코드 상태 | 역할 경계, 후보 방법론, 데이터·평가·운영 위험 | 비제품 조사로 포함 |

필요 저축액처럼 기존 산식이 계산한 진단 지표를 설명하는 것은 재무 설계가 아니다.
반면 그 부족액을 해소하기 위해 어떤 자산이나 상품을 얼마만큼 보유·매매할지
처방하면 재무 설계에 해당한다.

## 3. 현재 시스템과 역할 경계

현재 Backend는 은퇴 필요자금, 준비자금, 생애 현금 흐름, 필요 저축액 같은 진단
수치를 결정론적으로 계산한다. AI는 Django가 전달한 snapshot과 계산 완료된
보고서 지표를 읽고 설명하며, 직접 업무 DB를 수정하지 않는다.

현재 역할은 다음과 같다.

| 주체 | 현재 허용 역할 | 현재 금지 역할 |
|---|---|---|
| LLM Agent | 질문 답변, 입력 보조, 검증 오류 설명, 기존 차트·진단 수치 설명 | 새 자산배분안·상품 구성·매매 계획 생성, 원본에 없는 수치 생성 |
| 결정론적 코드 | 이미 합의된 진단 산식 실행, 입력·출력·권한 검증 | 미승인 자산배분 공식·optimizer·backtest 실행 |
| Django | 사용자·세션·업무 데이터 소유, 진단 보고서 계산·저장, 승인 검증 | LLM 출력만으로 재무 설계 결과나 투자 행동 확정 |
| 사용자·도메인 검토자 | 입력 확인, 변경 승인, 진단 결과 검토 | 연구 결과의 자동 제품 채택 |

향후 재무 설계 요구사항이 별도로 채택되더라도 LLM이 수치 계산의 단일 원천이
되어서는 안 된다. LLM은 비정형 의도 해석과 설명에 사용할 수 있지만, 수치 계산,
제약 충족, 재현 가능한 평가에는 버전이 고정된 결정론적 구현과 독립 검증이
필요하다. 이 문장은 향후 설계 원칙이며 P12에서 해당 구현을 만든다는 뜻이 아니다.

## 4. 자산배분 후보 접근법 조사

자산배분은 주식·채권·현금과 같은 서로 다른 자산 범주에 투자 금액을 나누는
행위다. 투자 기간과 위험 감내 수준에 따라 적절한 구성이 달라질 수 있고, 시간이
지나 비중이 바뀌면 리밸런싱을 고려한다. 이 자체가 개인의 미래 행동을 정하는
재무 설계이므로 현재 제품에는 연결하지 않는다.

| 접근법 | 개념 | 주요 데이터·가정 | 조사에서 확인된 위험 | 현재 판정 |
|---|---|---|---|---|
| 동일·고정 비중 | 정해진 규칙으로 자산 범주를 나눔 | 허용 자산 범주, 고정 규칙, 리밸런싱 기준 | 단순하지만 개인 목표·제약을 충분히 반영하지 못할 수 있음 | 문헌 비교만 수행 |
| 생애주기·glide path | 은퇴 시점에 가까워질수록 구성을 변화시킴 | 현재 나이, 은퇴 시점, 인출 시점, 위험 가정 | 같은 목표연도라도 경로와 은퇴 전후 가정이 달라질 수 있음 | 문헌 비교만 수행 |
| 평균-분산·최소분산 | 기대수익과 공분산을 이용해 위험·수익 조합을 탐색 | 수익률 시계열, 기대수익, 공분산, 제약 | 입력 추정 오차에 민감하고 표본 밖 성과가 불안정할 수 있음 | 문헌 비교만 수행 |
| Black–Litterman | 시장 기준 추정치와 별도 전망을 결합 | 시장 비중, 공분산, 전망과 신뢰도 | 전망·신뢰도의 근거가 약하면 정교한 형태로 오류를 확대할 수 있음 | 문헌 비교만 수행 |
| Risk Parity·HRP | 수익 전망보다 위험 기여나 상관 구조를 중심으로 배분 | 변동성·상관관계, 군집 방식, 관측 기간 | 기간·군집·공분산 추정에 따라 결과가 달라지고 시장 국면 변화에 취약 | 문헌 비교만 수행 |
| 목표·부채 기반 접근 | 미래 현금 유출과 목표 달성 위험을 중심으로 구성 | 생애 현금 흐름, 물가, 수명, 인출·비용 가정 | 가정 수가 많고 진단 지표에서 행동 처방으로 쉽게 범위가 확장됨 | 현재 제품 범위 밖 |

Markowitz의 평균-분산 연구는 분산투자의 고전적 출발점이지만, DeMiguel,
Garlappi, Uppal의 표본 밖 비교에서는 추정 오차 때문에 여러 최적화 모델이 단순
동일 비중 기준을 일관되게 이기지 못했다. HRP는 공분산 행렬 역산과 집중·불안정
문제를 줄이려는 대안이지만 데이터와 방법 선택 위험이 사라지는 것은 아니다.
이는 특정 방법을 채택할 근거가 아니라 복잡한 계산 결과를 곧바로 사용자에게
처방해서는 안 된다는 근거다.

## 5. 데이터 요구와 현재 공백

현재 프로젝트에는 재무 진단에 필요한 나이, 은퇴 예정 나이, 금융·연금·부동산
자산, 부채, 소득·지출, 재무 목표와 기존 보고서 산식이 있다. 이 데이터는 현재
상태와 은퇴 준비 격차를 진단하는 데 사용된다.

자산배분 설계에는 이와 다른 데이터와 결정이 필요하다.

- 구조화되고 검증된 위험 감내도와 손실 수용 범위
- 유동성 하한, 투자 제한, 세금·수수료·거래비용
- 자산·상품을 일관된 자산 범주로 매핑하는 기준
- 시점과 버전이 고정된 수익률·변동성·상관관계 자료
- 생존편향과 미래정보 누수를 막는 point-in-time 구성 정보
- 데이터 출처, 이용 허가, 재배포 조건, 수정·결측 처리 정책

현재 계약에는 이 항목들이 자산배분 입력으로 동결되어 있지 않다. P12에서는 새
필드를 만들거나 기존 정성정보를 위험 감내도로 해석하지 않는다. 금융시장 자료도
다운로드하거나 저장하지 않는다.

향후 실제 데이터 검토가 승인될 경우에도 KRX 시세정보는 이용 목적에 따라 별도
계약이 필요할 수 있고, KOSIS 통계는 API가 제공하는 단위·출처·주석 같은
metadata와 함께 다뤄야 한다. 데이터 접근 가능성이 제품 사용 권한을 뜻하지는
않는다.

## 6. 평가 관점

P12는 optimizer나 backtest를 실행하지 않는다. 다음 항목은 향후 재무 설계 범위가
별도로 채택될 경우 먼저 정의해야 할 평가 조건이다.

### 계산·데이터 평가

- 같은 입력·버전에서 같은 결과가 나오는 재현성
- 비중 합계·상하한·금지 조건 등 제약 충족
- 관측 기간과 가정 변화에 대한 민감도
- 학습·선정 기간과 평가 기간을 분리한 표본 밖 검증
- 단순 기준선과의 비교 및 거래비용 반영
- 결측·이상치·시장 급변 시 실패 동작
- 데이터·산식·코드 버전과 결과의 연결 가능성

### LLM 평가

- 진단 설명이 Backend 원본 수치와 일치하는지
- 원본에 없는 비중·상품·수익률을 생성하지 않는지
- 재무 설계 요청을 지원 범위 밖으로 안내하는지
- 불확실성과 데이터 부족을 숨기지 않는지
- 다른 사용자·세션의 금융정보를 사용하지 않는지

### 현재 P12 완료 판정

- 제품 경계와 금지 사항이 명시되어 있다.
- 후보 접근법이 채택안이 아닌 문헌 조사로 구분되어 있다.
- 사용자별 결과, 공식, 실행 코드, 시장 데이터가 없다.
- 데이터·평가·운영 위험과 열린 결정이 기록되어 있다.
- 제품 계약이나 runtime 파일을 변경하지 않는다.

## 7. 운영·보안 위험

| 위험 | 영향 | 현재 통제 |
|---|---|---|
| 범위 누수 | 진단 설명이 투자 처방처럼 노출될 수 있음 | 제품 경계와 지원 범위 밖 응답을 문서·Agent·화면에 명시 |
| LLM 수치 생성 | 존재하지 않는 수익률·비중·상품 근거를 만들 수 있음 | 구조화된 원본 진단 수치만 설명하고 새 설계 수치 생성 금지 |
| 추정·모델 위험 | 과거 자료에 맞춘 방법이 미래에도 유효하다고 오인할 수 있음 | P12에서 계산·백테스트·성과 주장을 하지 않음 |
| 데이터 권리 | 시세·지수 자료의 이용·재배포 조건을 위반할 수 있음 | P12에서 시장 데이터를 수집하지 않음 |
| 금융정보 노출 | 연구·trace에 고객 snapshot이나 결과값이 남을 수 있음 | 합성 사용자도 만들지 않고 실제 금융정보를 사용하지 않음 |
| 자동 채택 | 연구 문장이 tool·화면·운영 공식으로 전환될 수 있음 | 별도 요구사항과 도메인·보안·계약 검토 전 연결 금지 |
| 설명 책임 | 사용자가 진단을 보장·추천으로 오해할 수 있음 | 출처·기준일·한계와 지원 범위를 함께 표시 |

생성형 AI에는 사실과 다른 내용을 자신 있게 생성하거나 입력 데이터의 민감정보를
부적절하게 노출할 위험이 있다. 금융 진단 설명도 모델 출력만 신뢰하지 않고
결정론적 후검증, 최소 데이터, 권한 분리와 감사 가능한 버전을 유지해야 한다.

## 8. D10 인수 내용

D10 Function Calling과 Agent runtime 담당자는 P12 결과를 다음처럼 소비한다.

1. 현재 등록 도구를 검색·검증된 snapshot 조회와 출력 후검증 범위로 유지한다.
2. `calculate_asset_allocation`, portfolio optimizer, 상품 추천 도구를 추가하지 않는다.
3. 기존 진단 보고서 지표는 Backend가 계산하고 AI는 준비된 snapshot만 조회한다.
4. 자산배분 질문은 일반 금융 지식 설명 또는 지원 범위 안내로 처리한다.
5. 아래 열린 결정은 현재 구현 TODO가 아니라 향후 범위 확장 전 검토 목록으로 남긴다.

## 9. 열린 결정

- 제품이 재무 진단 이후 재무 설계까지 확장될 필요가 있는가
- 확장 시 어떤 사용자 결과와 위해 가능성을 요구사항으로 승인할 것인가
- 금융 도메인·법무·보안 검토와 최종 책임자를 어떻게 지정할 것인가
- 사용할 수 있는 시장·상품 데이터와 이용 조건을 어떻게 검증할 것인가
- 계산 방법, 기준선, 평가 기간과 실패·rollback 기준을 누가 승인할 것인가

이 결정들이 닫히기 전에는 자산배분 구현 작업을 만들지 않는다.

## 10. 근거 자료

모든 외부 자료의 확인일은 2026-09-05다.

- U.S. SEC, [Asset Allocation and Diversification](https://www.investor.gov/introduction-investing/getting-started/asset-allocation): 자산배분, 투자 기간, 위험 감내도, 분산과 리밸런싱의 기본 개념.
- U.S. Department of Labor, [Target Date Retirement Funds — Tips for ERISA Plan Fiduciaries](https://www.dol.gov/agencies/ebsa/about-ebsa/our-activities/resource-center/fact-sheets/target-date-retirement-funds-tips-for-erisa-plan-fiduciaries): glide path와 은퇴 전후 가정 차이.
- Harry Markowitz, [Portfolio Selection](https://doi.org/10.1111/j.1540-6261.1952.tb01525.x), *The Journal of Finance*, 1952: 평균-분산 포트폴리오 선택의 고전적 근거.
- Fischer Black and Robert Litterman, [Global Portfolio Optimization](https://people.duke.edu/~charvey/Teaching/BA453_2006/Black_Litterman_Global_Portfolio_Optimization_1992.pdf), 1992: 시장 기준 추정치와 전망 결합 접근.
- Victor DeMiguel, Lorenzo Garlappi, Raman Uppal, [Optimal Versus Naive Diversification](https://ideas.repec.org/a/oup/rfinst/v22y2009i5p1915-1953.html), *The Review of Financial Studies*, 2009: 추정 오차와 표본 밖 단순 기준선 비교.
- Marcos López de Prado, [Building Diversified Portfolios that Outperform Out of Sample](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2708678), 2016: Hierarchical Risk Parity와 전통적 최적화의 불안정성 문제.
- NIST, [AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework): 생성형 AI를 포함한 AI 시스템의 신뢰성과 위험 관리.
- 한국거래소, [데이터 수신방법](https://openapi.krx.co.kr/contents/OPP/DATA/OPPDATA003.jsp): 시세정보 이용 목적과 계약 고려사항.
- KOSIS, [OpenAPI 이용 안내](https://kosis.kr/serviceInfo/openAPIGuide.do): 공식 통계 수치와 단위·출처·주석 metadata 제공 방식.
