# 은퇴 몬테카를로 계산 규칙

상태: **MVP v1 내부 계산 명세 작성. 확률 경로 생성기·집계 엔진·전용 테스트는 미구현.**

`feat/ai-retirement-monte-carlo`에서 구현할 기준이다. 2026-09-08 확인한
`origin/master`의 `9afc694`에서 분기했으며, 현금흐름 구현이 포함돼 있다.
이번 작업은 브랜치 준비와 명세 작성까지다. 아래 예시는 합성 검산 자료이며 실제
몬테카를로 실행 결과, 시장 전망, 권장 수익률 또는 서비스 연결 완료를 뜻하지 않는다.

## 1. 목적과 작업 경계

동일한 고객 조건에 여러 연간 수익률 경로를 적용해 **계획 기간 동안 연말 계산
잔액이 한 번도 음수가 되지 않은 경로의 비율**과 나이별 잔액 분포를 추정한다.

- [기존 내부 모델](../models.py)의 고객 조건·가정·검증을 재사용한다.
- 각 경로의 적립·연금·생활비·고갈 계산은
  [`calculate_cashflow_path`](../cashflow.py)에 맡긴다. 현금흐름 공식을 복제하지 않는다.
- 수정 범위는 `ai-pjt/retirement/`다. BE·FE, Agent 라우팅·개별 로직·컨텍스트·
  재무상담 매뉴얼·RAG·공용 도구 등록·실행 설정은 변경하지 않는다.
- 표준 라이브러리만 사용한다. API key, 외부 시세 API, DB, LLM은 필요 없다.
- 기존 BE의 준비율을 변경하거나 몬테카를로 성공확률과 같은 지표로 취급하지 않는다.
- What-if, 실제 snapshot adapter, 외부 요청·응답 및 서비스 연결은 후속 작업이다.

계산 흐름은 `입력 검증 → 수익률 경로 생성 → 기존 현금흐름 계산 → 전체 경로 집계`다.
생성기·단일 경로 계산·집계를 분리해, 나중에 동일한 수익률 경로를 What-if에서
재사용하고 집계만 별도의 명시적 경로로 검산할 수 있게 한다.

## 2. 입력과 시간 기준

고객 입력에 새 필드를 요구하지 않고 `RetirementProfile`과
`SimulationAssumptions`를 사용한다. 이는 **내부 모델의 재사용**이며 기존 form이나
DB 데이터가 이미 연결됐다는 의미는 아니다.

| 기호 | 기존 필드 | 의미·검증 |
|---|---|---|
| `a0`, `ae` | `current_age`, `end_age` | 현재 나이부터 종료 나이까지 양 끝 포함 |
| `T` | `ae - a0 + 1` | 경로당 연도 수. 같은 나이면 1년, 최대 103년 |
| `m` | `annual_return_mean` | 명목 단순 연수익률의 산술 평균. 유한한 값, `m > -1` |
| `v` | `annual_return_volatility` | 같은 단순 연수익률의 연 표준편차. 유한한 값, `v >= 0` |
| `i` | `annual_inflation_rate` | 모든 경로에 동일하게 적용하는 고정 연물가율. 유한한 값, `i > -1` |
| `N` | `num_paths` | 동일 가중치 경로 수. 정수 1~100,000, 기존 기본값 1,000 |
| `seed` | `seed` | 재현용 0 이상 정수. 기존 기본값 0 |

비율은 소수 비율이다. 예를 들어 `0.05`는 5%이며 평균과 변동성을 로그수익률
모수로 해석하지 않는다. 세 시장 가정 `m`, `v`, `i`는 계속 필수다. 누락값을
시장 평균으로 채우거나 코드에서 투자성향별 추천값을 정하지 않는다.
`bool`, 문자열, 비유한 값 등 기존 모델이 거부하는 입력도 계속 거부한다.

수익률은 물가를 차감하지 않은 명목 수익률 기준이다. 세금·수수료를 별도로 계산하지 않는다.
연도별 금액은 물가가 반영된 **명목 원 단위**이며 현재가치로 다시 할인하지 않는다.
연말 현금흐름 순서·이미 은퇴한 경우·연금 일정·음수 잔액 이월은
[현금흐름 계산 규칙](cashflow-rules.md)을 그대로 따른다.

## 3. 수익률 분포: 총수익 배수의 로그정규분포

MVP에서는 `G = 1 + r`에 로그정규분포를 적용한다. `r`은 단순 연수익률이고,
`G`는 투자 원금에 대한 연말 배수다. 이 선택은 기존의 `r > -1` 계약과 맞는
**프로젝트의 모델링 가정**이며 실제 시장에 대한 적합성 검증 결과가 아니다.

로그정규분포는 로그를 취한 변수가 정규분포인 양수 변수의 분포다.
[NIST의 정의·평균·표준편차 공식](https://www.itl.nist.gov/div898/handbook/eda/section3/eda3669.htm)을
이 입력 계약에 맞게 정리하면, `v > 0`일 때 다음과 같다. 아래의 `mu`, `sigma`는
내부 로그수익률 모수이며 고객이 입력한 `m`, `v`와 구분한다.

```text
g       = 1 + m
sigma²  = ln(1 + (v / g)²)
sigma   = sqrt(sigma²)
mu      = ln(g) - sigma² / 2
Z       ~ Normal(0, 1)
r       = exp(mu + sigma × Z) - 1

이론상 E[r] = m, Std[r] = v, r > -1
```

유한한 표본의 평균·표준편차가 정확히 `m`, `v`가 되도록 경로를 재조정하지 않는다.
검산용 `m=0.05`, `v=0.10`이면 `mu ≈ 0.044275460810`,
`sigma ≈ 0.095023190429`다. 이 수치는 표시용 근사이며 계산에는 반올림 전 값을 쓴다.

- 경로 간·연도 간 충격은 독립·동일 분포라고 가정한다.
- 평균·변동성은 모든 연도에 동일하다. 상품별 자산배분, 상관관계, 시계열 의존성,
  시장 국면, 극단 사건 모형, 리밸런싱은 이번 MVP에 없다.
- 물가·생활비 일정·적립·연금은 무작위로 바꾸지 않는다. 물가와 수익률의 상관관계도 없다.
- 완전 손실 `r = -1`과 그 이하의 손실은 현재 현금흐름 계약 밖이다. 이를 지원하려면
  모델·엔진·명세를 함께 변경해야 한다.

### 변동성 0

`v == 0`이면 모든 경로의 모든 연도에 **입력 `m`을 그대로** 사용한다.
로그·지수 변환을 거치거나 난수를 소비하지 않는다. 각 경로는 기존
`calculate_cashflow(profile, assumptions)`와 정확히 일치해야 한다.

이때 나이별 모든 분위수는 같은 잔액이고, 성공확률은 해당 고정 경로의 성공 여부에
따라 0 또는 1이다. 이는 가정상 결과이지 현실에서 성공·실패가 확정됐다는 의미가 아니다.

## 4. 수치 범위와 계산 오류

수학적으로 허용되는 입력도 부동소수점으로 계산하지 못할 수 있다.

- 작은 값의 정밀도를 위해 `log1p`·`expm1` 등을 사용하고, 모수 변환에서 불필요한
  나눗셈·제곱 overflow를 피한다. 위 수학식을 무조건 같은 연산 순서로 옮기지는 않는다.
- `v > 0`인데 변환된 표준편차가 수치적으로 0이 되면 조용히 고정 경로로 바꾸지 않는다.
  표현 가능한 동등한 계산을 사용하거나 명시적인 수치 범위 오류로 처리한다.
- 매우 작은 `G` 때문에 `r`이 정확히 `-1`로 반올림될 수도 있다. 변환 모수·생성된
  수익률의 유한성과 `r > -1`을 검사한다. overflow·비유한 값·범위 이탈은 계산 오류다.
- 수익률을 경계값으로 자르거나 다시 추출하지 않는다. 실패한 경로를 버리고 `N`을
  줄이는 동작도 하지 않는다. 이러한 보정은 정의한 표본과 집계 대상을 바꾼다.
- 현금흐름 계산 오류와 분위수 집계의 비유한 연산도 전체 실행 오류로 처리한다.
  재무적 고갈은 정상 계산 결과이지만 수치 오류는 실패 경로 1개로 집계하지 않는다.
- 오류 발생 시 성공확률·부분 집계는 반환하지 않는다. 오류에는 단계·필드명과
  가능한 경우 경로 인덱스·나이만 담고, 입력 금액·고객 원문·전체 경로는 넣지 않는다.

결과의 금액을 0으로 자르거나 epsilon·반올림으로 고갈 판정을 바꾸지 않는다.
수치 비교 테스트의 허용오차와 금융 판정 기준은 분리한다.

## 5. 난수·재현성·경로 순서

초기 구현 기준은 **호출마다 독립된 `random.Random(seed)` 인스턴스 하나**와
`rng.gauss(0.0, 1.0)`이다. 전역 `random.seed()` 또는 공유 RNG를 사용하지 않는다.
독립 인스턴스는 난수 상태를 공유하지 않으며, 정규 난수 API와 버전별 재현성 제한은
[Python 3.13 공식 문서](https://docs.python.org/3.13/library/random.html)에 따른다.

1. 경로 인덱스 `0..N-1` 순서로, 각 경로 안에서는 나이 `a0..ae` 순서로 생성한다.
2. `v > 0`이면 경로당 `T`번 `gauss`를 호출한다. 경로마다 같은 시드로 재초기화하지 않는다.
3. 자산이 0·음수이거나 생활비가 없더라도 해당 연도의 수익률을 생성한다. 고갈 후에도
   종료 나이까지 생성·계산한다. 고객의 재무 상태가 난수 소비 순서를 바꾸면 안 된다.
4. 같은 입력·시드·코드·Python 버전·실행 환경에서 반복 호출한 결과는 같아야 한다.
   다른 코드가 전역 RNG를 사용하거나 호출 사이에 다른 고객을 계산해도 영향이 없어야 한다.
5. 계산 기간·시장 가정·시드가 같고 `N`만 늘어나면 기존 앞쪽 경로의 수익률은 유지한다.
   기간 `T`가 바뀌면 뒤 경로의 난수 배치도 바뀌므로 같은 경로를 보장하지 않는다.
6. 최초 구현은 직렬 실행이다. 공유 RNG를 여러 스레드에서 호출하거나 병렬화·벡터화로
   추출 순서를 바꾸는 최적화는 별도 검증 없이 추가하지 않는다.

규칙 식별자는 `retirement-mc-v1`로 정한다. 결과에는 가정·시드·경로 수·계산 기간과
모델 버전·RNG 방식·실행 Python 버전을 확인할 수 있는 메타데이터를 둔다.
분포·추출 순서·현금흐름·집계 규칙을 바꿀 때는 버전 변경과 회귀 검증이 필요하다.
시드만으로 Python 버전·플랫폼 간 비트 단위 동일 결과를 약속하지 않는다.

다른 시드는 다른 난수열 검증에 사용하되, 고객의 성공확률이나 잔액까지 반드시
달라진다고 단정하지 않는다. 수익이 적용될 자산이 없는 입력 등이 있기 때문이다.

## 6. 경로 성공·고갈 판정

`C[k, a]`는 경로 `k`의 나이 `a` 연말 계산 잔액이다.

```text
first_depletion_age[k] = C[k, a] < 0인 최초 a, 없으면 None
success[k]            = first_depletion_age[k] is None
success_count         = 성공 경로 개수
depletion_count       = N - success_count
success_probability   = success_count / N
depletion_probability = depletion_count / N
```

이미 구현된 `CashflowResult.first_depletion_age`를 사용하며 별도의 임계값을 만들지
않는다. 현재 나이부터 종료 나이까지 검사하므로 미래 은퇴 이전의 계산 연도도 포함한다.
정확히 0인 잔액은 성공을 유지한다. 중간에 음수였다가 최종 잔액이 양수가 돼도 실패다.

확률은 내부에서 0~1의 값으로 유지하고 퍼센트 변환은 표시 계층에서 한다.
분모는 항상 요청한 전체 `N`이다. 전부 성공·전부 고갈·경로 1개도 정상 집계한다.
고갈은 연말 기준이며 연중 모든 지출의 지급 가능성이나 실제 차입 여부를 판정하지 않는다.

## 7. 결과 집계 규칙

다음은 구현할 내부 결과의 의미다. 외부 JSON 키·HTTP 경로·Agent 도구 스키마는
아직 정하지 않는다. 결과는 기존처럼 불변 구조로 만들며, 파생값의 원천을 통일해
경로 수·확률·히스토그램·마지막 연도 요약이 서로 어긋나지 않게 한다.

| 결과 | 정의 |
|---|---|
| 실행 메타데이터 | 5절의 가정·시드·기간·반복 수·버전 정보. 고객 원문 자동 로깅은 하지 않음 |
| 성공·고갈 개수와 확률 | 6절 정의. 성공 개수 + 고갈 개수 = `N` |
| 최초 고갈 나이별 개수 | 각 계산 나이에 처음 고갈된 경로 수. 0개인 나이도 포함하고 나이순으로 제공 |
| 미고갈 개수 | `first_depletion_age is None`인 경로 수. 성공 개수와 같음 |
| 나이별 잔액 P10·P50·P90 | 각 나이에서 전체 `N`개 연말 잔액을 모아 각각 계산 |
| 최종 잔액 P10·P50·P90 | 나이별 잔액 집계의 마지막 연도와 동일 |
| 최종 부족액 P10·P50·P90 | 경로별 `max(-final_balance, 0)`을 먼저 만든 뒤 전체 `N`개 값에서 계산 |

최초 고갈 개수의 합은 `depletion_count`여야 한다. 미고갈 나이를 종료 나이나
임의의 숫자로 치환하지 않는다. 고갈 나이의 평균·중앙값은 MVP 필수 출력에서 제외해
미고갈 경로와 고갈 경로를 같은 나이 표본으로 섞지 않는다.

### 분위수 정의

고갈·회복 경로와 음수 잔액을 포함한 **전체 경로**를 동일 가중치로 집계한다.
성공 경로만 골라내지 않는다. 원본 경로 순서를 바꾸지 않고 해당 나이의 값 복사본을
오름차순 정렬한다. `q = 0.10, 0.50, 0.90`에 대해 선형 보간을 사용한다.

```text
x = 해당 시점의 N개 값을 오름차순 정렬한 배열 (0부터 인덱싱)
h = (N - 1) × q
j = floor(h)
w = h - j
Q(q) = (1 - w) × x[j] + w × x[min(j + 1, N - 1)]
```

이는 [NumPy 문서의 `linear`, Hyndman–Fan type 7 정의](https://numpy.org/doc/stable/reference/generated/numpy.quantile.html)와
같은 수학적 규칙이다. **NumPy 의존성을 추가한다는 뜻은 아니다.** `N=1`이면 모든
분위수는 그 값이고, `q=0`, `q=1`을 검산할 때는 각각 최솟값·최댓값이다.
같은 값·음수·홀수·짝수 표본도 같은 규칙을 적용하고 보간 결과를 반올림하지 않는다.

- P50은 표본 중앙값이며, 평균 수익률을 반복한 고정 현금흐름 결과와 같다고 가정하지 않는다.
- 나이별 분위수를 이어 붙인 선은 특정 경로 하나가 아니다. P10~P90은 시점별
  잔액 분포 요약이지 전체 생애 경로의 80% 동시 포함 보장이나 성공확률의 신뢰구간이 아니다.
- 음수 잔액은 누적 미충당 부족액이며 실제 대출이 아니다. 부족액을 연도별로 더하지 않는다.
  최종 부족액이 0이어도 중간 고갈은 남는다. 부족액 분위수는 잔액 분위수의 부호를
  단순히 바꿔 만들지 않고, 위 표의 경로별 부족액 표본에서 계산한다.
- 계산된 확률은 입력 가정과 유한한 `N`에 따른 추정치다. 0%·100%도 현실의 보장이
  아니다. 표본 오차의 신뢰구간·시장 가정 보정은 후속 검증 과제로 남긴다.

## 8. 손계산·회귀 테스트 기대값

### A. 변동성 0과 기존 엔진 동등성

[현금흐름 예시 A](cashflow-rules.md#8-손계산-기대값)의 입력에 `v=0`을 적용한다.
경로 수·시드에 상관없이 모든 경로의 59·60·61세 잔액은 각각
`12,200,000`, `12,820,000`, `11,702,000`원이다. 성공확률은 1이고 해당 나이의
P10·P50·P90은 모두 같은 값이다. 예시 C를 같은 방식으로 반복하면 최종 잔액은
양수여도 모든 경로가 61세에 처음 고갈하므로 성공확률은 0이어야 한다.

### B. 고갈 후 회복과 전체 표본 분위수

아래 경로는 **집계 검산을 위해 직접 지정한 수익률**이지 로그정규 난수 출력이 아니다.
생성기를 거치지 않고 기존 엔진과 집계를 따로 검증하는 입력이다. 금액은 모두 원 단위다.

- 현재·은퇴 60세, 종료 61세, 기초 금융자산 120원, 적립 0원.
- 60~61세 월 생활비 10원, 61세에만 월 연금 20원, 물가 0.
- `N=4`. 명시적 수익률은 평균 가정을 대체한다.

| 경로 | 60·61세 수익률 | 60세 잔액 | 61세 잔액 | 최초 고갈 | 경로 성공 |
|---|---|---:|---:|---|---|
| 0 | `(-0.5, 0)` | -60 | 60 | 60세 | 아니오 |
| 1 | `(0, 0)` | 0 | 120 | 없음 | 예 |
| 2 | `(0.5, 0)` | 60 | 180 | 없음 | 예 |
| 3 | `(1.0, 0)` | 120 | 240 | 없음 | 예 |

경로 0은 61세 기초 잔액 -60에 투자수익을 적용하지 않고 연금 240원, 생활비 120원을
반영해 60원으로 회복한다. 결과는 성공 3개·고갈 1개, 성공확률 `0.75`다.
최초 고갈 개수는 60세 1개·61세 0개이고 미고갈은 3개다.

| 집계 시점·대상 | P10 | P50 | P90 |
|---|---:|---:|---:|
| 60세 잔액 | -42 | 30 | 102 |
| 61세 = 최종 잔액 | 78 | 150 | 222 |
| 최종 부족액 | 0 | 0 | 0 |

예를 들어 최종 잔액 P10은 `h=3×0.1=0.3`이므로 `0.7×60 + 0.3×120 = 78`이다.
최종 잔액 또는 최종 부족액만 보고 성공확률을 1로 계산하면 잘못된 구현이다.

## 9. What-if와 후속 연결 경계

What-if는 기준 입력과 변경 입력에 **같은 경로 인덱스·같은 나이의 시장 수익률**을
적용한다. 수익률 생성부는 고객의 적립액·생활비·은퇴 여부를 읽어 난수를 바꾸지 않는다.
공통 경로를 한 번 생성해 재사용할 수 있도록 현금흐름 실행과 분리한다.

초기 What-if는 현재·종료 나이와 시장 가정을 유지하는 월 적립액·은퇴 나이·생활비
변경을 대상으로 한다. 은퇴 나이에 맞는 생활비 구간 재검증과 새 불변 프로필 생성은
What-if 브랜치의 책임이다. 기존 프로필·컨텍스트·저장된 고객 정보를 수정하지 않는다.

계산 기간이나 시장 가정까지 다른 비교는 시드만 맞춰 같은 시장 경로라고 선언하지
않는다. 공통 기간·충격의 정렬과 분포 변환 정책을 별도로 정한다.
외부 API, 실제 snapshot 매핑, 결과 DTO, 인증·세션·timeout·화면 표시는 후속
adapter·연동 단계에서 정한다. 이 명세만으로 기존 서비스에서 호출되는 것은 아니다.

## 10. 구현 순서와 인수 항목

이번 문서 다음에는 **수익률 경로 생성기와 기본 테스트**를 구현한다. 이후 공통
현금흐름 호출·집계, 경계 검증, 합성 샘플 실행 순서로 진행한다.
브랜치와 권장 커밋 단위는 [README](../README.md)에 정리한다.

다음 항목은 모두 **향후 구현·자동 테스트 대상**이며 아직 완료 표시하지 않는다.

- [ ] 모수 변환을 별도 수학 기대값으로 검증하고 단순 수익률 평균·표준편차 의미를 보존한다.
- [ ] `N × T`의 유한한 `r > -1` 경로, 현재 나이부터의 인덱스 대응을 검증한다.
- [ ] 변동성 0이면 난수 호출 없이 기존 고정 엔진과 일치한다. 예시 A/C를 재사용한다.
- [ ] 같은 시드의 반복 실행·전역 RNG 비간섭·경로별 난수 진행·경로 수 확장 시 앞쪽 경로 보존을 검증한다.
- [ ] 고갈·잔액 0·적립·은퇴 나이 변화가 시장 경로 생성을 바꾸지 않는다.
- [ ] 예시 B의 성공·고갈·회복·히스토그램·분위수 기대값을 자동 테스트로 전환한다.
- [ ] 전부 성공·전부 고갈·정확히 0·미세 음수·경로 1개·계산 1년을 검증한다.
- [ ] 분위수의 음수·중복값·홀수·짝수 표본·양 끝·순서·원본 비변경을 검증한다.
- [ ] 모수 변환·수익률 생성·현금흐름·집계의 수치 오류가 보정이나 부분 확률로 바뀌지 않는다.
- [ ] 결과 불변성·파생값 일치·오류와 `repr`의 금융 입력 비노출을 검증한다.
- [ ] 고정 시드의 비영 변동성 표본을 정해진 허용오차로 점검한다. 표본 모멘트의 정확한 일치나 시장 적합성을 주장하지 않는다.
- [ ] 합성 입력에서 실제 확률 계산을 실행하고 가정·경로 수·성공확률·분위수·한계를 출력한다.
- [ ] 기존 현금흐름·입력 검증 73개 테스트가 계속 통과한다.

`N <= 100,000`은 기존 입력 상한이지 응답 시간이나 메모리 보장이 아니다.
초기 기본값은 유지하되 전체 경로의 무거운 연간 상세 객체를 모두 보관할 필요는 없다.
각 경로의 요약과 나이별 집계에 필요한 값 중심으로 보관하고, 분위수 계산은 정확한
위 정의를 따른다. 시간·메모리를 측정한 뒤 최적화를 별도 작업으로 판단하며,
임의로 경로 수를 줄이거나 근사 분위수로 바꾸지 않는다.
