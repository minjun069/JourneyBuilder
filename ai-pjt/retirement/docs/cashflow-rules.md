# 은퇴 현금흐름 계산 규칙

상태: **MVP v1 내부 계산 명세 — 엔진·기본·경계 조건 테스트 구현. 계산 샘플 확장 예정.**

`feat/ai-retirement-cashflow`의 계산 기준이다. 아래 규칙과 손계산 기대값에 맞춰
[엔진](../cashflow.py)을 구현한다. 사용 방법과 구현 범위는
[엔진 가이드](cashflow-engine.md)를 참고한다. 서비스 연결을 뜻하지 않는다.
예시의 수익률·물가는 검산을 위한 합성 값이며 시장 전망이 아니다.

## 1. 적용 범위와 기존 모델

[내부 모델](../models.py)의 단위·불변성·기간 검증을 그대로 사용한다.

- `RetirementProfile`: 기초 금융자산, 월 적립액, 나이, 생활비·연금 일정.
- `SimulationAssumptions`: 고정 연수익률과 고정 연물가율을 읽는 명시적 계산 가정.
- `AssetPoint`: 해당 나이 연도의 말 잔액. 최초 입력 자산과 구분한다.

한 번에 고객 한 명의 경로 하나만 계산한다. 부동산·부채·연금 계좌 잔액·계좌 납입·
일시금·세금·수수료·급여 성장·재취업은 추가하지 않는다. 기존 BE 보고서나 준비율을
대체하지 않으며 DB·HTTP·LLM·Agent·컨텍스트를 호출하거나 수정하지 않는다.
실제 snapshot 변환과 지원 범위 안내는 이후 adapter 작업으로 남긴다.

## 2. 시간과 금액 기준

`current_age`를 `a0`, `retirement_age`를 `ar`, `end_age`를 `ae`로 표기한다.

- 계산 나이는 `a0, a0 + 1, ..., ae`, 연도 수는 `ae - a0 + 1`이다.
- 현재 나이와 종료 나이가 같아도 한 해를 계산한다. 과거 은퇴 연도는 재계산하지 않는다.
- 최초 `liquid_assets`는 `a0` 연초 잔액이며 결과의 첫 연말 잔액이 아니다.
- 한 나이는 온전한 12개월로 취급한다. 생일·월중 은퇴·일할 계산은 하지 않는다.
- 입력 금액은 원 단위 정수이고, 내부 계산·결과는 유한한 원 단위 실수이다.
- 계산 중 정수 절삭·원 단위 반올림을 하지 않는다. 표시용 반올림은 후속 표시 계층의 책임이다.
- 수익률·물가는 연간 소수 비율이다. `0.05`는 5%이며 월 수익률로 변환하지 않는다.

## 3. 연간 현금흐름

### 3.1 금융자산 적립 `S(a)`

```text
a < ar  : S(a) = monthly_savings × 12
a >= ar : S(a) = 0
```

은퇴하는 해부터 적립을 중단한다. 이미 은퇴했으면 입력 월 적립액이 양수여도 이
계산에서는 반영하지 않는다. 월 적립액은 명목 총액으로 고정하며 물가로 늘리지 않는다.
은퇴 전 일반 생활비는 별도로 차감하지 않는다. 입력된 적립액은 그 지출을 감안해
금융자산에 추가할 금액이며 소득-지출 잉여나 연금 계좌 납입을 다시 더하지 않는다.

### 3.2 연금 수령액 `P(a)`

```text
P(a) = 12 × sum(p.monthly_amount
               for p in pension_incomes
               if p.start_age <= a <= p.end_age)
```

시작·종료 나이를 모두 포함하고, 여러 연금이 겹치면 합산한다. 수령기간 밖이거나
명시적 빈 목록이면 0이다. 은퇴 여부와는 독립된 일정이므로 은퇴 전 수령 일정도
반영한다. 수령액은 명목 금액으로 유지하며 자동 물가 연동·수령액 추정을 하지 않는다.

이 계산의 입력에서는 적립액과 연금 수령액을 서로 중복되지 않는 현금흐름으로
본다. 실제 데이터에서 연금 수령액이 이미 적립액에 포함됐다면 그대로 둘 다 넣지
않아야 한다. 이를 구분하는 것은 향후 adapter의 책임이며 여기서 임의 차감하지 않는다.

### 3.3 은퇴 생활비 `E(a)`

`i = annual_inflation_rate`, `t = a - a0`이다. `M(a)`는 그 나이를 포함하는 생활비
구간의 현재가치 기준 월 총액이다.

```text
a < ar  : E(a) = 0
a >= ar : E(a) = M(a) × 12 × (1 + i)^t
```

생활비는 은퇴하는 해부터 반영한다. 현재 연도의 물가 배수는 1이고, 미래 은퇴
시점에는 현재부터 은퇴까지의 물가 상승도 반영한다. 이미 은퇴했어도 물가는 현재
나이부터 시작하며 과거 은퇴 나이까지 소급하지 않는다. 구간이 바뀌어도 지수를
초기화하지 않는다. 음의 물가율은 기존 모델의 허용 범위인 `i > -1` 안에서 허용한다.

기존 모델이 보장하는 비중복·완전한 은퇴 생활비 일정만 사용한다. 누락 구간을 0으로
메우거나 마지막 금액을 연장하지 않고, 구간 금액을 평균 내지 않는다. 명시적 0원
구간은 그대로 0원이다.

## 4. 연간 계산 순서

MVP는 **연초 양수 잔액에 수익 적용 → 연말 적립·연금 유입·생활비 차감** 순서다.
적립금과 연금은 유입되는 해에 투자수익을 얻지 않고 다음 해부터 원금에 포함된다.
생활비도 연말에 일괄 차감한다. 같은 해의 유입·지출을 합산하는 연 단위 근사이지,
실제 월별 입출금이나 연중 지급 가능성을 검증하는 모델이 아니다.

`B(a)`는 연초 계산 잔액, `r(a)`는 해당 연도의 수익률, `I(a)`는 투자손익,
`C(a)`는 연말 계산 잔액이다.

```text
B(a0) = profile.liquid_assets
I(a)  = max(B(a), 0) × r(a)
C(a)  = B(a) + I(a) + S(a) + P(a) - E(a)
B(a + 1) = C(a)
```

음의 수익률은 양수 투자 원금의 손실로 반영한다. 모든 자산을 동일 수익률로 계산하며
상품별 비중·리밸런싱·상관관계는 지원하지 않는다. 위 식의 `max`는 투자 원금에만
적용하며, 연말 계산 잔액 자체를 0으로 잘라내지 않는다.

## 5. 고갈과 부족액 이월

- `C(a) < 0`이면 그 연도 말에 고갈된 것으로 판정한다. 정확히 0이면 고갈이 아니다.
- 최초 고갈 나이는 처음 음수가 된 나이이며, 없으면 `None`이다.
- 고갈 후에도 계획 종료까지 계산하고, 이후 잔액이 회복돼도 최초 고갈 이력을 지우지 않는다.
- 양수 잔액은 남은 금융자산, 음수 잔액은 **계산상 누적 미충당 부족액**을 뜻한다.
  음수는 실제 금융자산이나 대출 잔액을 뜻하지 않는다.
- 음수 잔액에는 수익률을 적용하지 않는다. 손실률 때문에 부족액이 줄어들거나,
  양의 수익률 때문에 부채 이자가 생기는 계산을 하지 않는다.
- 부족액을 다음 해로 이월하고, 다음 해 순유입은 기존 부족액을 먼저 상쇄한다.
  이는 계산 지속을 위한 규칙이지 자동 차입·생활비 지급 완료를 의미하지 않는다.

연말 부족액은 `gap(a) = max(-C(a), 0)`으로 정의한다. 이 값은 해당 시점의 미충당
잔액이므로 여러 해의 `gap`을 더해 총 부족액이라고 표시하지 않는다. 최종 부족액을
표시한다면 마지막 해의 `gap`을 사용하며, 회복 이후 최종 부족액이 0이어도 과거
고갈 사실은 유지한다. 실제 부채 상환·이자·신용 한도는 별도 모델이 필요하다.

이 브랜치는 고갈 이력만 제공한다. 확률 경로의 성공 판정·성공확률·분위수 집계는
몬테카를로 브랜치의 책임이며 최종 잔액만으로 성공이라고 표시하지 않는다.

## 6. 고정 수익률 실행과 공통 계산부

고정 수익률 실행에서는 모든 연도에 `annual_return_mean`을 동일하게 적용하고,
물가도 `annual_inflation_rate`로 고정한다. 이는 평균 경로의 확률적 기대값 추정이
아니라 **고정 가정에 따른 단일 계산 결과**이다.

`annual_return_volatility`, `num_paths`, `seed`는 기존 입력 모델의 검증은 유지하되
고정 계산에는 사용하지 않는다. 이 값들만 바꿔도 같은 고정 계산 결과여야 한다.
비영(非零) 변동성을 입력했다고 확률 계산을 수행한 것으로 표시하지 않는다.

엔진은 고정 실행과 연도별 수익률을 소비하는 공통 계산부를 분리한다.
공통 계산부는 다음 규칙을 따른다.

- 명시적 경로의 길이는 `ae - a0 + 1`과 정확히 같고, 인덱스 0은 현재 나이 연도이다.
- 각 수익률은 bool이 아닌 유한한 숫자이고 `-1`보다 커야 한다.
- MVP 경로 컨테이너는 list 또는 tuple, 원소는 int 또는 float로 제한한다.
  generator·배열 라이브러리 객체·문자열 파싱은 지원하지 않는다.
- 길이가 맞지 않으면 거부한다. 경로를 자르거나 반복하거나 평균값으로 채우지 않는다.
- 명시적 경로는 고정 평균을 **대체**한다. 평균에 추가로 더하지 않는다.
- 전달된 입력과 경로를 수정하지 않는다. 난수 생성·외부 시세 조회는 하지 않는다.
- 같은 현금흐름·고갈 규칙을 적용하고, 고정값을 반복한 경로는 고정 실행과 일치해야 한다.

고정 실행은 `calculate_cashflow`, 공통 계산부는 `calculate_cashflow_path`, 결과는
`CashflowYear`와 `CashflowResult`이다. HTTP 요청·응답 규격,
난수 분포·시드 처리·시장 가정의 출처, What-if 변환은 여기서
추가하지 않는다. 완전 손실 `-1`이나 레버리지 손실까지 지원하려면 기존 모델과
계산 명세를 함께 재검토해야 하며 조용히 보정하지 않는다.

## 7. 결과와 오류 처리 기준

각 연도 결과에서 나이·기초 잔액·적용 수익률·투자손익·적립액·연금액·
생활비·기말 잔액·기말 부족액을 검산할 수 있어야 한다. 전체 결과에서는 연도별
경로, 최종 잔액, 최초 고갈 나이를 확인할 수 있어야 한다.

연도 수만큼의 `AssetPoint`를 만들고 각 점에는 해당 연도의 기말 잔액을 담는다.
나이는 연속·오름차순이며 첫해 기초 잔액을 별도 연말 점으로 중복 추가하지 않는다.
결과도 불변 구조로 제공한다. 내부 필드명은 엔진 가이드에 정리하며 외부 JSON
직렬화는 여기서 확정하지 않는다.

기존 입력 검증을 우회하거나 `None`·문자열·잘못된 값을 0으로 바꾸지 않는다.
유한한 입력이라도 큰 금액·물가 거듭제곱·누적 계산으로 비유한 값이나 overflow가
발생하면 명시적 계산 오류로 종료한다. `NaN`·무한대·상한으로 대체한 결과나 성공한
것처럼 보이는 부분 경로를 반환하지 않는다. 오류에는 고객 입력 원문을 넣지 않는다.

반올림이나 epsilon으로 음수 잔액을 0으로 바꾸지 않는다. 테스트의 실수 허용오차는
수치 비교를 위한 것이며 고갈 판정의 임계값을 바꾸는 수단으로 사용하지 않는다.
표시에서 0원으로 반올림되더라도 내부 음수 잔액의 고갈 상태는 유지한다.

## 8. 손계산 기대값

아래는 **손계산 테스트의 기대값**이다. A/B는 기본 테스트, C는 경계 조건
테스트에서 검증한다. 기존 `samples.py` 입력과는 별개이며 모든 금액은 원 단위다.

### A. 수익 적용 순서·은퇴 전환·연금 종료·생활비 구간 변경

- 현재 59세, 은퇴 60세, 종료 61세, 기초 자산 10,000,000원.
- 월 적립 100,000원, 생활비는 60세 월 100,000원·61세 월 200,000원.
- 연금은 60세에만 월 50,000원, 수익률 `0.1`, 물가 `0`.

| 나이 | 기초 잔액 | 투자손익 | 적립 | 연금 | 생활비 | 기말 잔액 |
|---|---:|---:|---:|---:|---:|---:|
| 59 | 10,000,000 | 1,000,000 | 1,200,000 | 0 | 0 | 12,200,000 |
| 60 | 12,200,000 | 1,220,000 | 0 | 600,000 | 1,200,000 | 12,820,000 |
| 61 | 12,820,000 | 1,282,000 | 0 | 0 | 2,400,000 | 11,702,000 |

첫해 적립금에 당해 수익을 붙이면 표와 달라져야 한다. 60세에는 적립이 중단되고
연금과 생활비가 함께 반영된다. 연금의 시작·종료가 같은 60세는 한 해 수령이다.

### B. 은퇴 전부터 누적하는 물가와 구간 전환

- 현재 60세, 은퇴 62세, 종료 63세, 기초 자산 5,000,000원.
- 적립·연금 없음, 수익률 `0`, 물가 `0.1`.
- 생활비는 62세 월 100,000원, 63세 월 200,000원이며 모두 현재가치 기준.

| 나이 | 경과 연수 | 생활비 계산 | 연간 생활비 | 기말 잔액 |
|---|---:|---|---:|---:|
| 60 | 0 | 은퇴 전 | 0 | 5,000,000 |
| 61 | 1 | 은퇴 전 | 0 | 5,000,000 |
| 62 | 2 | 100,000 × 12 × 1.1² | 1,452,000 | 3,548,000 |
| 63 | 3 | 200,000 × 12 × 1.1³ | 3,194,400 | 353,600 |

은퇴 시점이나 생활비 구간 전환 시 물가를 다시 1부터 적용하지 않는다.

### C. 정확히 0인 잔액·고갈·회복 이력

- 현재·은퇴 60세, 종료 63세, 기초 자산 1,200,000원, 월 적립 0원.
- 생활비는 60~63세 월 100,000원, 연금은 62~63세 월 300,000원.
- 수익률·물가 모두 `0`.

| 나이 | 기초 잔액 | 연금 | 생활비 | 기말 잔액 | 기말 부족액 | 그 시점의 최초 고갈 나이 |
|---|---:|---:|---:|---:|---:|---|
| 60 | 1,200,000 | 0 | 1,200,000 | 0 | 0 | 없음 |
| 61 | 0 | 0 | 1,200,000 | -1,200,000 | 1,200,000 | 61 |
| 62 | -1,200,000 | 3,600,000 | 1,200,000 | 1,200,000 | 0 | 61 |
| 63 | 1,200,000 | 3,600,000 | 1,200,000 | 3,600,000 | 0 | 61 |

최종 잔액이 양수여도 최초 고갈 나이는 61세다. 전년에서 음수 잔액이 이월된 해에는
수익률이 `0.1`이든 `-0.1`이든 투자손익은 0이어야 한다. 이것은 초기 프로필에 음수
자산을 허용한다는 뜻이 아니다. 초기 음수 자산은 기존 모델처럼 거부한다.

## 9. 구현·인수 항목

- [x] 위 A/B 기대값을 자동 테스트로 전환한다.
- [x] 위 C 고갈·회복 기대값을 경계 조건 자동 테스트로 전환한다.
- [x] 이미 은퇴한 입력에서 과거 기간을 재계산하지 않고 적립을 반영하지 않는다.
- [x] 현재·은퇴·종료 나이가 같은 입력은 정확히 한 개의 연말 결과를 만든다.
- [x] 겹치는 연금은 합산하고 종료 다음 해에는 제외한다. 연금 없음·0원도 보존한다.
- [x] 양수 원금의 음의 수익률, 음의 물가율, 음수 이월 잔액의 손익 0을 검증한다.
- [x] 고정 수익률과 동일 값의 명시적 경로가 일치하고 잘못된 경로는 거부된다.
- [x] 반복 호출·경로 재사용 시 원본이 변하지 않고 결과가 동일하다.
- [x] 큰 입력으로 인한 비유한 중간값·결과를 오류로 처리한다.
- [ ] 기존 기반 테스트를 유지하고 합성 샘플을 실제 계산 실행으로 확장한다.

엔진·결과 모델과 A/B/C 및 경계 조건 테스트를 구현했다. 요구사항별 테스트 위치와
검증 범위는 [검증 기록](cashflow-validation.md)에 정리한다. 계산 샘플은 후속
확장 작업에서 확인한 뒤 표시한다. 임시 확률값이나 가짜 계산 출력을 만들지 않는다.
