결정일: 2026-09-10. 사용자 결정에 따른 **기능·모듈 측 연결 기준 확정**이다.
BE/FE 담당자의 수락, 공통 정책 변경, 배포·운영 성능 승인 또는 실제 시장 보정 완료를 뜻하지 않는다.

## 1. 적용 값과 정책 경계

기계적으로 전달할 원본은 [simulation-policy.json](simulation-policy.json)이다.
버전은 `simulation-mvp-2026-09-10.v1`이며 엔진/JSON 계약/패키지 버전과 구분한다.

| 필드 | 값 | 의미 |
|---|---|---|
| `annual_return_mean` | `0.04` | 연 단순수익률의 명목 산술평균 4%. CAGR/로그수익률/보장금리 아님 |
| `annual_return_volatility` | `0.10` | 같은 수익률의 연 표준편차 10%. 최대 손실·±10% 경계 아님 |
| `annual_inflation_rate` | `0.02` | 현재 나이 기준 생활비에 적용할 고정 연 물가율 2% |
| `num_paths` | `1000` | 초기 MVP 경로 수. 정밀도·응답시간·운영 상한 보장 아님 |
| `seed` | `42` | 재현용 기술 설정. 금융적 의미나 좋은 결과를 선택하는 용도 없음 |

서버 연결부는 검토한 정책의 `assumption_values` **다섯 필드만** 함수에 전달한다.
정책 JSON 전체나 `policy_version`을 `assumption_values`에 넣으면 미지원 키로 거절된다.
정책 로딩·출처·기준 식별·운영 제한은 BE 책임이며 엔진은 파일/환경변수/네트워크를 읽지 않는다.
이 파일은 전달/소스 검증 자료로 sdist에 포함되지만 설치용 wheel에는 포함되지 않는다.
BE가 정책을 어디에 배치하고 검증할지는 연결 담당과 확인한다. 설치만 하면 자동 적용되지 않는다.

현재 엔진은 금융자산 종류별 비중·상관관계·상품별 금리를 분리하지 않는다.
예금/주식/펀드/채권/가상자산의 지원 평가액을 하나로 합쳐 같은 수익률 경로를 적용한다.
따라서 결과는 **공통 가정 기반의 부분 범위 분석**이며 개인별 보유 포트폴리오의 예측값이 아니다.
주식 60%·채권 40%로 실제 재배분하거나 그 비중을 사용자의 보유 비중으로 간주하지 않는다.
세금·수수료·환율·유동성 제약도 별도 모델링하지 않으므로 세후 실현 수익률로 표현하지 않는다.

## 2. 근거와 한계

### 평균 수익률 4%

프로젝트 [공통 정책](../../../contract-fixtures/financial-calculation/v1/policy.json)의
`2026-09-07.v1`에서 `financial_return_rate=0.04`를 **명시적 정책 선택**으로 채택했다.
별도 원화 시장 데이터 추정/검증을 한 값은 아니며 `calibration_period=null`로 기록한다.
기존 준비자금 계산 일부는 `aggressive_financial_return_rate=0.05`를 사용한다.
숫자/경제적 의미가 같다고 주장하거나 BE 공통 정책을 자동 복사·변경하지 않는다.
동일 snapshot이어도 기존 준비율과 MC의 포함 자산·가정·평가 시점이 다를 수 있다.

### 변동성 10%

[Blackstone의 혼합자산 예시](https://www.blackstone.com/en-emea/pws/essentials-of-private-credit/)는
2025-12-31 기준 글로벌 주식 60%·채권 40% 예시에 연환산 변동성 10.4%를 제시한다.
이를 **크기 참고**로 삼아 MVP의 공통 가정을 10%로 선택했으며 직접 추정치로 복제하지 않았다.
자료의 표 제목은 10년, 설명의 계산 기간은 2011-01~2025-12로 표기가 달라 이 기간을
우리 모델의 측정 기간으로 채택하지 않는다. 통화·구성·표본 빈도 및 연환산 방식도 다르다.
이 출처만으로 한국 사용자의 위험이나 예측 정확도를 검증했다고 주장하지 않는다.
변동성을 높이는 것이 모든 입력에서 더 보수적인 성공확률을 만든다고 가정하지 않는다.

### 물가 2%

[한국은행 물가안정목표](https://www.bok.or.kr/portal/main/contents.do?menuNo=200291)의
중기 소비자물가 목표 2%와 프로젝트 정책을 근거로 선택했다. 매년의 실제 물가/개인별
소비 바구니를 예측한 값은 아니다. 생활비에만 현재 나이부터 적용하며 연금 수령액이나
월 적립액을 자동으로 물가 연동하지 않는다. 물가가 이미 반영된 미래 금액을 중복 인상하지 않는다.

### 경로 수와 재현성

1,000경로는 [기존 합성 성능 기록](analysis-performance.md)을 참고한 초기 연결 선택이다.
실제 기간을 51년으로 자르거나 1,000경로를 모든 운영 환경의 성능 보장으로 해석하지 않는다.
동일 입력·가정·엔진·난수 알고리즘·Python 환경에서 같은 시드를 사용하고, What-if 한 호출에서
기준/변경이 공통 시장 경로를 사용한다. 고정 시드는 반복 결과만 고정하며 표본 오차를 제거하지 않는다.

모형 내 성공 비율이 50% 부근이면 `1.96 * sqrt(0.5 * 0.5 / N)`의 95% 정규 근사 오차는
N=1,000에서 약 ±3.1%p, N=5,000에서 약 ±1.4%p다.
이는 독립 경로의 **표본추출 오차** 근사이며 현실의 예측 오차/모형 오차까지 포함하지 않는다.
0%/100% 주변에 같은 대칭 근사를 적용하지 않으며 두 결과 차이의 오차와도 구분한다.
자산 P10/P50/P90은 성공확률의 신뢰구간이 아니다.
[통계 근거: NIST](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)

## 3. 이번 기능 범위

- 보고서 버튼 → BE 인증 API → 설치된 Python 함수 직접 호출. AI 서버·Agent·LLM은 변경하지 않는다.
- 기준안 1개 + 변경안 1개. 월 적립 총액·은퇴 나이·기간별 생활비 세 가지를 조합할 수 있다.
- 기존 준비율과 MC 성공확률은 별도 표시. **변경 후 준비율 재계산은 제외**한다.
- 성공확률/변경 차이와 자산 분포를 제공하며 성공 보장·투자 추천·최적화로 표현하지 않는다.
- 저장된 동일 기준 입력을 사용하고, What-if를 원본 DB·보고서·대화 컨텍스트에 저장하지 않는다.
- 시나리오 영구 저장/불러오기·LLM 설명·실시간 외부 금융 API는 제외한다.
- 부동산·부채 상환·일회성 목표는 미반영 사실을 안내하는 부분 분석을 허용한다.
  필수 입력 누락/불명확한 연금/분류 오류는 기존 규칙대로 실행 오류이며 임의 0으로 채우지 않는다.

화면에는 다음 짧은 안내를 두고 상세 `계산 기준`에서 가정/제외 범위/각 `notices`를 설명한다.

> 공통 가정 기반의 금융자산·저축·연금·생활비 시뮬레이션입니다. 부동산·부채 상환·일회성 목표 지출은 반영하지 않습니다.

팝업이나 긴 경고문이 필수는 아니지만 원본 `notices`는 BE 응답에서 버리지 않는다.
기존 준비율의 실제 원천·분자/분모는 BE/FE 확인 대상이다. 화면의 고정값 28%/67%를
실제 결과로 재사용하지 않고 미준비 상태로 표시한다. MC만 연결한 상태와 두 지표 연결 완료는 구분한다.

## 4. 변경/출시 기준

정책 값·해석·포함 범위가 바뀌면 정책 버전을 올리고 근거·검증 결과를 다시 기록한다.
실시간 자동 갱신은 하지 않으며 최초 공개 전, 정책 근거 변경 또는 모델 변경 시 재검토한다.
입력·정책·모델·환경이 달라지면 이전 기준과 비교를 중단하고 재실행한다.
공통 재무 정책이 갱신되어도 이 전용 정책을 몰래 변경하지 않는다.

출시 전에는 가정 민감도·여러 시드/경로 수·실제 BE 기간/동시성·사용자 표시를 검증한다.
합성 검증은 원화 시장 보정이나 개인별 금융 검토를 대신하지 않는다. 개인별 자산 위험 추정으로
범위를 확장하려면 자산 배분·원화 기준 수익률/상관관계·세금/비용 등을 별도 설계·검증해야 한다.

정책 결정은 다른 담당자의 API·배포·FE 변경 승인이 아니다. 해당 기술 계약은
[BE 연결 확인서](be-integration-checklist.md)에서 답변을 확인한 후 연결한다.
