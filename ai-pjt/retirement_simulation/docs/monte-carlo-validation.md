# 몬테카를로 경계 조건 검증 기록

상태: **브랜치 4번 작업 완료 — 조합형 독립 검산·상한·수치 오류·재현성 검증 확대.**

2026-09-08, 4번 작업 완료 시점에 Miniforge `retirewise-ai`의 Python 3.13.15에서 독립 모듈 테스트
**162개 통과: 기존 136개 + 신규 경계 테스트 26개**를 확인했다.
subtest 조합은 테스트 메서드 개수에 더하지 않는다.
후속 5번 샘플 CLI의 19개 검사를 더한 현재 전체는 181개이며
[샘플 가이드](monte-carlo-samples.md)에 정리한다.

신규 테스트는 [`test_monte_carlo_edges.py`](../tests/test_monte_carlo_edges.py)에 있다.
[3번 기본 테스트](../tests/test_monte_carlo.py), 수익률 생성기·현금흐름·모델·기존
샘플 테스트는 유지했다. 이번 검증에서 계산 코드의 수정이 필요한 문제는 발견하지
않았으므로 **테스트와 문서만 변경**했다. 계산 규칙·모델 버전·입출력 모델은 바꾸지 않았다.

## 1. 재실행 방법

저장소 루트에서 실행한다. 이미 설치한 Miniforge 환경을 그대로 사용하며 추가
패키지·API key·DB·네트워크·실제 고객 정보가 필요하지 않다.

```bash
# 독립 모듈 전체 회귀 검사
conda run -n retirewise-ai python -B -m unittest discover -s ai-pjt/retirement_simulation/tests -q

# site-packages 없이도 동일한 검사 실행
conda run -n retirewise-ai python -S -B -m unittest discover -s ai-pjt/retirement_simulation/tests -q

# 이번 4번 작업의 26개 테스트만 자세히 확인
conda run -n retirewise-ai python -S -B -m unittest discover -s ai-pjt/retirement_simulation/tests -p test_monte_carlo_edges.py -v
```

공용 `make g1-check`에 자동 포함된 검사가 아니다. 일반 실행과 `-S` 실행 모두
확인했으며, 전체 AI·BE·FE 테스트 통과를 뜻하지 않는다.
추가 일회성 점검으로 발견된 162개 테스트를 역순 실행해 모두 통과하는지 확인했다.
엔진 가이드의 Python 예제도 재실행했고, 변경 문서의 로컬 파일 링크 42개가 존재하는지
확인했다. 이 점검들은 위 테스트 개수에 별도로 더하지 않는다.

### 독립 Decimal 대조

`reference_batch`는 운영 코드의 현금흐름·결과 모델·분위수 도우미를 호출하지 않고
**80자리 Decimal**로 연간 현금흐름·최초 고갈·경로별 최종 부족액을 계산한다.
`reference_percentiles`는 정확한 십진 가중치 `0.1`, `0.5`, `0.9`로 type 7을
별도로 계산한다. 참조 계산기 자체도 손으로 확인한 다음 사례와 먼저 대조한다.

| 나이 | 경로 A 잔액 | 경로 B 잔액 |
|---|---:|---:|
| 59 | 300 | 240 |
| 60 | 330 | 390 |
| 61 | 75 | -60 |

이 사례는 은퇴 당해 적립 중단, 중첩 연금의 시작·종료, 생활비 구간 변경과 물가
누적을 함께 포함한다. 최초 고갈은 61세 1개이며 최종 잔액 P10/P50/P90은
`-46.5 / 7.5 / 61.5`원이다. 합성 검산 금액이지 시장 전망이 아니다.

자동 조합은 다음과 같다.

- 명시적 경로 **81개 배치**: 은퇴 전환·이미 은퇴·마지막 해 은퇴의 3가지 일정 ×
  물가 `-0.02/0/0.03` × 경로 수 `1/2/17` × 로컬 시드 `0/13/97`.
  수익률은 정해진 6개 합성 값에서 선택한다. 로그정규 표본이라고 표시하지 않는다.
- 생성 경로 **27개 배치**: 3가지 일정 × 3가지 평균·변동성 조합 × 3가지 시드,
  각각 19개 경로. 생성기가 만든 동일한 경로에 독립 현금흐름·집계를 적용해 대조한다.
  생성기 자체의 분포 적합성을 새로 입증한 것은 아니다.
- 변동성 0 **162개 조합**: 3가지 일정 × 평균 3개 × 물가 3개 × 경로 수 3개 ×
  시드 2개. 나이별·부족액 분위수는 기존 고정 현금흐름과 **정확히 같은 float**여야
  하며 RNG를 만들지 않는다. 큰 정수 시드도 포함한다.

Decimal에는 전달된 float의 값을 그대로 변환한다. 금액 대조의 허용오차는 상대
`1e-10`, 절대 `1e-7`원이다. 십진 참조와 float 계산의 미세한 차이를 허용하는
테스트 기준이며 **실제 고갈 판정에는 적용하지 않는다**. 최초 고갈 개수와 성공·고갈
비율은 정확히 비교한다. 0·미세 음수는 기본 테스트와 명시적 경계 사례로 따로 확인한다.

### 순서·배율·기간·반복 실행

- 전체 경로들의 순열은 집계와 원본 입력을 바꾸지 않는다. 경로 안의 연도 순서를
  바꿔도 같다는 뜻은 아니다.
- 경로를 복제하면 개수는 배로 늘고 성공 비율은 같다. **type 7 분위수는 복제 전과
  같다고 가정하지 않는다.** 예를 들어 `[-60, 60]`의 P10은 -48이지만 각 값을
  2번씩 넣으면 -60이다. 표본 수가 달라지면 보간 위치도 달라진다.
- 모든 금액을 2·8배 하면 같은 시장 경로에서 고갈 개수는 유지되고 금액 분위수는
  그 배율로 변한다. 이진 부동소수점에서 정확한 배율인 2의 거듭제곱으로 검증한다.
- **이미 생성한 경로를 명시적으로 잘라** 기간을 줄이면 앞쪽 잔액·최초 고갈
  히스토그램이 유지된다. `end_age`만 바꾸고 같은 시드로 다시 생성하는 것은 다르다.
- 배치를 나눠 계산한 성공·고갈 개수는 합산 가능하다. 전체 분위수는 전체 표본으로
  대조하며, 부분 분위수를 평균 내는 집계 API를 구현한 것은 아니다.
- 로컬 RNG를 사용하는 독립 호출 9개를 최대 3개 스레드에서 실행해 직렬 결과와
  비교한다. 오류 발생이나 다른 코드의 전역 난수 사용 뒤에도 반복 결과가 유지된다.
  엔진 내부 병렬화·서비스 동시성·처리량을 보장하는 부하 시험은 아니다.

## 3. 상한과 수치 오류

경로 수와 기간의 상한은 **서로 다른 테스트에서** 검증한다.

| 사례 | 실제 검사 |
|---|---|
| `N=100,000`, `T=1` | 비영 변동성으로 실제 생성·집계. 한 해 잔액의 별도 식 `12*r`로 전 경로의 고갈 개수·분위수 대조 |
| `N=7`, `T=103` | 18~120세, 은퇴·생활비·연금 전환을 포함한 생성 경로를 Decimal로 대조 |
| `N=3`, 현재 18세 또는 100세, 종료 120세 | 첫해·마지막 해 고갈과 모든 0개 히스토그램 구간의 인덱스 검증 |
| `N=4096/4097`, `T=1` | 섞인 큰 홀짝 표본의 잔액이 `k-1024`인 검산 경로. 순위 공식으로 분위수·고갈 대조 |

`N=100,000`과 `T=103`을 **동시에** 실행한 것은 아니며, 시간·메모리 상한을
테스트의 통과 조건으로 넣지 않는다. 구현의 공간 `O(N×T)`·분위수 정렬 시간
`O(T×N log N)` 특성이나 입력 상한이 서비스 응답 시간을 보장하지 않는다.

`-1` 바로 위 수익률은 그대로 받아들이고 `-1` 이하는 거부한다. 매우 큰 유한 수와
0 근처의 아주 작은 수의 보간은 정확한 `Fraction` 산술과 대조한다. 이 검사에서
보간 오차 허용치는 상대 `1e-14`, 절대 최소 양수 float 한 단위이며, 금액을
반올림하거나 수익률을 잘라내는 보정은 추가하지 않는다.

현금흐름 오류 11개 필드 `liquid_assets`, `savings`, `pension_income`,
`annual_expenses`, `inflation_factor`, `expenses`, `investment_return`,
`balance_after_return`, `balance_after_savings`, `balance_after_pension`,
`closing_balance`가 몬테카를로의 `cashflow` 단계 오류로 전달되는지 확인한다.
오류의 경로 인덱스·나이는 유지하고 입력 금액은 메시지에 넣지 않는다.

추가로 모수 변환, 두 번째 경로의 잘못된 난수, 세 번째 경로의 중간 연도 overflow,
나이별 집계 및 최종 부족액 집계에서 실행이 실패하는 경우를 검증한다. 일부 오류는
고정된 위치에 NaN 등을 주입하는 fault injection이며 실제 시장 데이터가 아니다.
완료된 앞쪽 경로가 있어도 부분 결과·줄어든 분모를 반환하지 않고, 난수를 재추출하지 않는다.
0원 생활비·은퇴 후 적립·비활성 연금의 미사용 극단 입력은 불필요하게 계산하지 않는다.

## 4. 남은 작업

전용 샘플 CLI와 사용 문서**도 완료했으며 [샘플 가이드](monte-carlo-samples.md)를 참고한다.
