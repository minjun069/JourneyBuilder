# 저장 입력 어댑터 확대 경계 검증 기록

상태: **입력 어댑터 브랜치 3번 확대 경계·회귀 검증 완료.**
기준 구현은 `7253c68`이며 [매핑 규격](input-mapping-rules.md)의 정책을 변경하지 않았다.
검증 중 구현 수정이 필요한 결함은 발견되지 않아 런타임 코드는 그대로 유지했다.
실제 저장 데이터 조회·BE API·FE 연결·배포·시장 가정 검증 완료를 뜻하지 않는다.

## 1. 대상과 변경 경계

- 구현: [input_adapter.py](../input_adapter.py), 공개 사용법: [입력 어댑터 가이드](input-adapter.md).
- 기존 기본 테스트: [test_input_adapter.py](../tests/test_input_adapter.py) 39개.
- 신규 확대 테스트: [test_input_adapter_edges.py](../tests/test_input_adapter_edges.py) 38개.
- 변경은 시뮬레이션 모듈 안의 새 테스트·검증 문서와 관련 문서 상태 갱신뿐이다.
  어댑터·모델·현금흐름·MC·What-if·CLI·export 코드는 수정하지 않았다.
- BE·FE·Agent·컨텍스트·매뉴얼·DB·공통 실행/의존성 설정·Jira는 변경하지 않았다.

테스트는 기존 기본 fixture와 별도의 작은 합성 입력만 사용한다. 실제 고객 정보,
외부 금융 데이터, API 키, Django 설정 또는 실행 중인 DB가 필요 없다.

## 2. 정책별 검증 범위

| 묶음 | 보강한 검증 |
|---|---|
| 구조·필수값 | 사용 금액/나이 전체에 null·bool·문자열·소수·Decimal/Fraction 거절, 중첩 필수 키 누락, generator 미소비 거절 |
| 원천 ID | 미지원 항목 확인용 목록도 행 구조·ID 자료형/중복 확인. 목표 항목 ID는 before/after 전체에서 중복 검사 |
| 없음 확인 | 옵션 자료형·잘못된 이름·중복/모순·하나만 확인된 두 빈 목록. 확인 순서가 결과를 바꾸지 않음 |
| 정수 금액 | 0·1·`2**53+1`·`10**400`을 정수로 보존. 평가액 0인 행의 양수 적립 보존 |
| 생활비 일정 | 나이 경계·단일 연도·역전·필수 은퇴 기간 coverage, 계산 범위 밖 중복 거절/공백 보존, 항목 순열·고정 여부·같은 이름으로 합산 결과가 바뀌지 않음 |
| 연금 기간 | 유한/종신 조합 검산, 수령 첫해/마지막 해 포함, 과거 종료/계획 후 개시, 기간 제한, 원천 순서·안내 index 보존 |
| 연금 원천 | 비 ASCII 숫자·부호·소수·내부 공백/줄바꿈·미지원 기간 거절. 범위 밖 연금도 필수 입력 검증. 명시적 0과 알 수 없는 예상액 구분 |
| 가정 | -1 경계의 인접 float, 미세 양수/음수 변동성, 큰 유한 값·float 변환 불가 정수, 경로/시드 상한·자료형·오류 우선순위 |
| 기존 엔진 연결 | 월→연 변환·생활비 물가 1회 적용·명목 연금, 직접 구성한 모델과 동일 What-if 경로 결과 대조 |
| What-if 경계 | 조기 은퇴 시 전체 생활비 교체 필요, 연금 개시 유지, 과거 은퇴 변경 거절, 이미 은퇴한 경우 저축 변경 효과 없음 |
| 범위 안내·실패 | 제외 재무정보는 안내만 추가하고 계산에 미반영. 뒤쪽 잘못된 행으로 전체 실패, 원본 불변·다음 실행 정상 |
| 독립성 | 24개 호출의 결과 격리·전역 난수 상태 유지, stdout/stderr 무출력, 안전한 오류·안내, 불변 결과와 생성자 검증 |

서비스용 가정의 합리적 범위나 경로 수 제한을 새로 정한 것은 아니다.
예를 들어 `num_paths=100000`과 큰 정수 시드는 **매핑 검증만** 수행하며 해당 규모의
경로를 생성하거나 운영 처리량을 검증하지 않는다. 큰 정수 금액이 모델에 들어가더라도
float 계산 불가 시 기존 `CashflowCalculationError`로 실패하는 경계를 따로 확인한다.

## 3. 독립적인 조합 검산

### 생활비: 130개 일정 조합

9개 후보 구간에서 0~3개를 선택한 `1 + 9 + 36 + 84 = 130`개 조합을 검사한다.
계획 기간은 60~63세이며 후보에는 계산 범위 밖 59세/64세, 단일 연도, 전체 기간,
경계에서 겹치는 구간이 포함된다. 실제 입력은 역순으로 전달해 정렬도 확인한다.

정답은 어댑터나 모델의 검증 함수를 호출해 만들지 않는다. 각 원천 구간에 속하는
나이의 개수를 `Counter`로 세어 다음 두 조건을 모두 만족하는지 직접 확인한다.

1. 원천 전체에 나타나는 모든 나이의 포함 횟수가 1이다. 비활성 구간 중복도 금지한다.
2. 필요한 60~63세가 각각 정확히 한 번 포함된다.

유효하면 원천 구간·월액 보존/정렬을 확인하고, 유효하지 않으면 `invalid_profile`의
`goal_periods` 경로로 거절하는지 확인한다. 모든 일정이 유효하다고 가정하거나
실패만으로 통과하지 않도록 성공/실패 조합이 모두 존재하는 것도 검사한다.

### 연금: 유한 128개·종신 32개 조합

계획 범위 4개 `(18~18, 40~45, 80~100, 100~120)`와 개시 나이 8개
`(1, 18, 39, 40, 41, 65, 100, 120)`를 사용한다.

- 유한 연금: 수령기간 1/2/10/120년을 추가 조합해 **128개**를 검사한다.
  실제 수령 나이 집합과 계획 나이 집합의 교집합을 직접 구한다. 각 나이의 월액,
  활성 일정 유무·원천 개시 나이·마지막 수령 나이, 기간 제한/범위 밖 안내를 대조한다.
- 종신 연금: **32개**에 대해 계획 내 각 나이가 개시 나이 이상인지로 월액을 검산한다.
  개시=종료인 한 해 수령, 종료 이후 개시의 제외 안내도 포함한다.

기대값은 기간 문자열을 제품 파서로 다시 파싱해서 만들지 않는다. 조합에 사용한
정수 나이·수령기간에서 직접 계산한다. 1세 개시나 120년 기간은 내부 규격의 경계
검사용이며, BE 폼의 더 좁은 입력 범위나 실제 상품 조건을 의미하지 않는다.

### 단위·현금흐름 손계산

현재 60세·은퇴 61세·종료 63세, 자산 1,000원·월 적립 2원·은퇴 월 생활비 5원,
62~63세 월 연금 3원, 수익률 0·물가율 0.5의 합성 사례를 검증한다.

| 항목 | 60세 | 61세 | 62세 | 63세 |
|---|---:|---:|---:|---:|
| 연 적립 | 24 | 0 | 0 | 0 |
| 연 생활비 | 0 | 90 | 135 | 202.5 |
| 연 연금 | 0 | 0 | 36 | 36 |

마지막 잔액은 `1000 + 24 - 90 - 135 + 36 - 202.5 + 36 = 668.5원`이다.
월 금액을 어댑터에서 미리 12배 하지 않고 생활비 물가는 엔진에서 한 번만 적용하며,
연금은 명목 고정액으로 남는지 검산한다. 이 수치는 시장 전망이나 권장 가정이 아니다.

## 4. 실패·동시 호출·독립성의 의미

- 같은 읽기 전용 합성 입력에 최대 3개 스레드로 24회 매핑한다. 일부 호출 직전에는
  별도의 잘못된 복사본을 실패시켜 오류가 다음 호출이나 다른 호출에 남지 않는지 본다.
  결과 프로필은 서로 다른 객체이고 원본·전역 난수 상태는 유지된다.
- 별도 `python -S -B` 프로세스에서 Django/FastAPI/HTTP 클라이언트/NumPy/LLM 관련
  import를 거절한 상태로 매핑한다. 함수 실행 중 `open`, `socket.socket`, `os.getenv`,
  `random.Random` 호출을 실패시키는 검증용 대체 함수를 적용해 독립 실행을 확인한다.
- 금액·이름·알 수 없는 키를 오류/안내/기본 repr에 넣지 않고 스트림에도 출력하지 않는지
  확인한다. traceback의 로컬 변수 기록까지 안전해진다는 뜻은 아니다.

이는 모듈의 상태 분리 검증이지 BE 동시성/성능 보장이나 DB snapshot 원자성 검증이 아니다.
호출 도중 다른 코드가 원본을 수정하지 않도록 보장하는 책임, 없음 확인 근거·세션 소유권,
운영에서 범위 안내를 사용자에게 보여주는 책임은 여전히 연결부에 있다.

## 7. 기타 금융자산 제외 보완 검증
