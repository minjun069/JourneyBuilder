# FE 전달용: 보고서 몬테카를로·What-if 연결

2026-09-10. 기능 담당이 확정한 범위와 **화면 연결 제안**이다.
FE 파일 수정·API 합의·실제 전달·배포는 하지 않았다. **현재 FE 담당자가 없어 화면 구현 담당은 미정**이다.
이 문서는 향후 화면 구현자가 사용할 초안이며 사용자가 FE까지 맡기로 했다는 뜻이 아니다.
API URL/HTTP envelope/상태코드는 기능 담당과 BE가 [기술 확인서](be-integration-checklist.md)에서 먼저 맞춘다.
화면은 담당자·수정 범위를 정한 뒤 연결하며, 그전에도 BE 설치/API와 API 단독 검증은 진행할 수 있다.

## 1. 만들 화면과 제외 범위

보고서에서 `[시뮬레이션 실행]` → 기준 결과 → 조건 편집 → `[변경 조건으로 비교]` 순서다.
초기에는 기준안과 변경안 **1개**만 나란히 비교한다. 세 조건을 조합하는 것은 가능하다.

- 기존 준비율은 별도 지표로 유지하고 MC를 준비율이라고 이름만 바꾸지 않는다.
- 기준/변경 성공확률, 성공확률 차이(%p), 나이별 자산 P10/P50/P90과 최종 잔액을 표시한다.
- 변경 후 준비율·자동 최적화/추천·시나리오 저장/불러오기·LLM 설명은 제외한다.
- 가정/경로 수/시드는 서버 관리다. 이번 화면에서 수익률·변동성 등을 사용자가 바꾸지 않는다.
- AI 채팅/Agent API는 사용하지 않는다. Python 실행은 BE에 설치된 모듈이 담당한다.

[현재 준비율 화면](../../../front-pjt/src/components/presentation/RetirementReadinessSlide.vue)의
28%/67%와 금액은 고정값이다. 실제 준비율의 원천·평가 시점은 기존 보고서 BE 담당과 확인한다.
실제 원천이 없으면 미준비 상태로 표시하고 고정값을 실제 결과처럼 사용하지 않는다.
MC만 실행 가능한 상태와 실제 준비율까지 함께 연결된 완료 상태를 구분한다.

## 2. 입력 UI와 요청 경계

브라우저는 인증된 상담/보고서에 대해 **실행 의도·서버 기준 식별자·가상 변경값만** 전달한다.
원본 재무정보·계산 가정·성공확률·없음 확인 여부를 브라우저가 권위 있는 값으로 제출하지 않는다.
기준 snapshot/정책/소유권 검사는 BE 책임이다.

| 조건 | 요청 의미 | UI 주의 |
|---|---|---|
| `monthly_savings` | 변경 후 월 **총** 적립액, 원 단위 정수 | 기존 750,000원→1,000,000원이면 250,000이 아닌 1,000,000 전달. 0은 중단 |
| `retirement_age` | 변경 후 은퇴 나이, 정수 | 현재/종료 나이·연금 개시 시점은 바뀌지 않음. 이미 은퇴한 사람의 은퇴 나이 변경은 미지원 |
| `retirement_expenses` | 기간별 월 생활비 **전체 일정 교체** | `{from_age,to_age,monthly_amount}` 목록. 나이 양끝 포함, 현재 가치 원/월, 공백/겹침 금지 |

생략/`null`은 유지다. `[]`는 생활비 유지가 아닌 오류다. 입력을 비웠다고 0으로 변환하지 않는다.
월 적립은 이미 은퇴한 사용자에게 효과가 없으므로 편집을 비활성화하거나 효과 없음을 안내한다.
은퇴를 앞당기면 새 은퇴 연도의 생활비도 사용자가 지정해야 한다. 기존 금액을 확장하는 UI라면
추가 구간/금액을 보여주고 확인받는다. 원본/연금 일정 자동 이동·임의 평균·빈 기간 0 보충은 금지한다.
단일 생활비 숫자 UI를 사용하면 모든 기간을 그 값으로 바꿀지 명시적으로 확인해야 한다.

논리 요청 예시는 다음과 같다. **아직 호출 가능한 HTTP API 규격이 아니며 이름/URL은 BE 확인 대상**이다.

```json
{
  "mode": "what_if",
  "baseline_key": "example-server-issued-key",
  "changes": {
    "monthly_savings": 1000000,
    "retirement_age": 58,
    "retirement_expenses": [
      {"from_age": 58, "to_age": 74, "monthly_amount": 1800000},
      {"from_age": 75, "to_age": 90, "monthly_amount": 1300000}
    ]
  }
}
```

BE는 검증 후 changes를 모듈의 `scenarios=[{scenario_id, changes}]` 1개로 감싼다.
FE가 `scenario_id`를 고객 ID/제목으로 만들거나 계산용 원본 정보를 덮어쓰지 않는다.
실제 기준 40세·은퇴 60세·종료 90세인 **합성 예시**이므로 사용자 값에 그대로 적용하지 않는다.

## 3. 결과 필드와 표시

아래 경로는 HTTP envelope 안의 위치가 아니라 **모듈 분석 객체 자체를 기준**으로 한다.
[전체 JSON 예시](handoff-examples.json)의 `examples[].module_output`을 화면 mock 검토에 사용할 수 있다.
이 파일 전체를 API 응답으로 가정하지 않는다. 기준/조합/오류 사례가 포함되어 있다.

| 모듈 필드 | 화면 용도·변환 |
|---|---|
| `baseline.success_probability` | 기준 확률. 0~1 → ×100으로 % 표시 |
| `scenarios[0].result.success_probability` | 변경 확률. 0~1 → ×100 |
| `scenarios[0].delta.success_probability_delta_pp` | 변경−기준, 이미 %p. **다시 ×100하지 않음** |
| `baseline.asset_percentiles[]` / 변경 `result.asset_percentiles[]` | `age`, `balance.p10/p50/p90`로 나이별 자산 분포 차트 |
| 기준/변경 `final_balance_percentiles` | 최종 명목 원화 잔액의 P10/P50/P90 |
| 변경 `delta.final_balance_delta` | 각 결과 분위수끼리 뺀 원 단위 차이. 경로별 차이의 분위수가 아님 |
| 기준/변경 `first_depletion_counts`, `never_depleted_count` | 최초 자금 부족 나이 분포와 미고갈 경로 수. 미고갈을 0세 고갈로 표시하지 않음 |
| `baseline_profile` / `scenarios[0].profile` | 실제 적용 입력·기간. 최초 폼과 비교 계산 결과를 혼동하지 않음 |
| `metadata`, `notices` | 실제 가정/경로 수/기간/버전·계산 범위. 서버 정책 버전/기준 키는 별도 envelope 확인 |

성공은 계획 기간의 **연말 잔액이 한 번도 음수가 되지 않은** 모의 경로다. 연중 지급능력·현실의
성공 보장은 아니다. 음수 잔액은 모형의 누적 미충당 부족액이지 실제 대출잔액이나 순자산이 아니다.
자산 P10~P90은 성공확률 신뢰구간이 아니며, P50 곡선도 단일 미래 경로가 아니다.

화면은 표시용 반올림만 하고 계산/비교는 BE가 반환한 원본 값을 사용한다.
작은 양수가 반올림으로 0%가 되면 `<0.1%` 같은 구분 표기를 사용한다. 표본 0%/100%를
불가능/확실함으로 표현하지 않고 0.1%p 차이를 검증된 개선으로 강조하지 않는다.
정밀도 한계와 관측한 시드 차이는 [검증 기록](handoff-validation.md)에 있다.

## 4. 짧은 안내와 계산 기준

결과 아래에는 다음 문구를 두고 상세 내용은 `계산 기준`에서 확인하게 한다.

> 공통 가정 기반의 금융자산·저축·연금·생활비 시뮬레이션입니다. 부동산·부채 상환·일회성 목표 지출은 반영하지 않습니다.

상세에는 정책 4%/10%/2%·1,000경로, 계획 기간, 명목 금액, 개인별 포트폴리오 추정이 아님을 표시한다.
`notices`는 아래와 같이 사람이 읽을 수 있게 변환하며 없는 코드를 임의 추가하지 않는다.

| 코드 | 안내 의미 |
|---|---|
| `partial_financial_scope` | 지정한 금융자산/현금흐름의 부분 분석 |
| `single_portfolio_assumption` | 자산별 비중·금리·변동성을 분리하지 않은 공통 가정 |
| `pre_retirement_cashflow_not_recalculated` | 월 적립 총액 사용, 소득−지출/은퇴 전 목표 재계산 안 함 |
| `pension_account_not_modeled` | 월 수령액 사용, 연금계좌 평가·납입·인출 별도 계산 안 함 |
| `real_estate_not_modeled` | 부동산 평가/처분·임대료·보증금·담보대출 미반영 |
| `liabilities_not_modeled` | 부채 원금·이자·상환 미반영 |
| `milestones_not_modeled` | 일회성 소득·지출 목표 미반영 |
| `confirmed_empty_financial_assets` / `confirmed_empty_pensions` | BE 원천에서 실제 없음이 확인된 경우만 반영 |
| `pension_outside_horizon` | 계획 기간 밖의 연금 수령은 계산 대상에서 제외 |
| `pension_horizon_limited` | 연금 수령을 계획 종료까지만 계산, 수명 추정 아님 |

전체 원본 안내 정보는 보존한다. 알 수 없는 코드가 추가되면 조용히 버리지 말고 일반 안내와 함께
개발 확인 대상으로 처리한다. 민감한 프로필/입력을 브라우저 로그·분석 이벤트에 덤프하지 않는다.

## 5. 상태/오류와 인수 기준

| 상태 | 동작 |
|---|---|
| 미실행 | 확률을 `계산 전`으로 표시. 0%로 채우지 않음 |
| 계산/비교 중 | 로딩·중복 버튼 방지. 완료 시간은 운영 측정 전 약속하지 않음 |
| 비교 성공 | 같은 응답의 기준/변경을 함께 갱신. 다른 기준끼리 차이 계산 금지 |
| 입력 부족/오류 | 안전한 필드별 수정 안내. 원본 금액/traceback이 담긴 서버 오류 노출 금지 |
| 기준 변경/만료 | 기준 재실행 유도. 편집 중 저장 정보가 변경되면 이전 비교 무효화 |
| 과부하/실패/timeout | 실패 상태·서버 정책에 맞춘 재시도. 이전 결과는 이전 결과로 구분 |

사용자가 두 번 요청한 경우 늦은 첫 응답이 최신 결과를 덮지 않게 요청 순서를 관리한다.
브라우저 요청 취소가 서버 계산 중단을 뜻하지 않으므로 BE 중복/취소 정책과 함께 확인한다.

- [ ] 화면 구현 담당과 시뮬레이션 관련 FE 수정 범위를 확정했다.
- [ ] API URL/envelope/status·기준 키·정책 버전 필드를 BE와 맞췄다.
- [ ] 실제 준비율 원천 또는 미준비 표시가 있고, 고정값을 실제 결과로 사용하지 않는다.
- [ ] 세 조건/조합·0/null·전체 일정·조기 은퇴 추가 기간·이미 은퇴한 입력을 검증했다.
- [ ] 확률/pp/원·분위수·모형 한계를 올바르게 표시하고 모든 범위 안내를 확인할 수 있다.
- [ ] 원본을 저장하지 않으며 실제 API로 입력 부족/실패/만료/오래된 응답을 검증했다.

화면 mock만 연결한 상태를 서비스 완료로 표시하지 않는다. 최종 실제 데이터 E2E는
[후속 작업 순서](handoff-next-steps.md)에 따라 함께 확인한다.
