# 은퇴 What-if 계산·비교 규칙

상태: **0~5번 브랜치·규칙·시나리오 생성·비교 계산·기본 및 확대 경계 테스트·전용 샘플 완료.**
아래는 내부 MVP 기준이며 실제 데이터·서비스 연결 완료를 뜻하지 않는다.
현재 구현된 변경 모델과 생성 함수의 규격은 [시나리오 생성 가이드](what-if-scenarios.md)에 있다.
배치 호출·결과·출처·오류 규격은 [비교 계산 가이드](what-if-engine.md)에 있다.
실제 합성 비교 실행은 [What-if 샘플 가이드](what-if-samples.md)를 참고한다.

2026-09-08 최신 `origin/master`의 `f0fe7ea`에서
`feat/ai-retirement-what-if`를 분기했다. 몬테카를로 MR !34의 병합을 포함한다.
[기존 내부 모델](../models.py), [현금흐름 규칙](cashflow-rules.md),
[몬테카를로 규칙](monte-carlo-rules.md)을 재사용하며 계산 공식을 복제하지 않는다.
이 문서의 예시는 합성 검산 자료이지 시장 전망·추천 조건·실제 고객 계산 결과가 아니다.

## 1. 목적과 작업 경계

같은 고객의 기준안과 명시적으로 바꾼 조건을 **동일한 시장 수익률 경로**에 적용해
성공확률·잔액·부족액이 얼마나 달라지는지 비교한다. 최적 조건을 자동 탐색하거나
LLM이 임의의 금액·은퇴 나이·연금을 채우는 기능이 아니다.

- 변경은 `ai-pjt/retirement_simulation/` 안으로 제한한다. 표준 라이브러리만 사용한다.
- Agent 라우팅·개별 로직·컨텍스트·재무상담 매뉴얼·RAG·공용 도구 등록은 수정하지 않는다.
- BE·FE·준비율·DB·공용 의존성·실행 설정은 수정하지 않는다.
- 실제 snapshot을 읽거나 저장된 고객 정보·대화 상태를 변경하지 않는다.
- 입력은 이미 검증된 `RetirementProfile`, 공통 `SimulationAssumptions`, 변경 조건이다.
  기존 서비스 form이 연결됐다는 뜻은 아니다. 외부 API·DTO·snapshot adapter·호출부는
  [전체 계획](../README.md)의 6·7단계에서 별도로 정한다.

비교의 기본 단위는 **기준안 하나와 변경안 하나**다. 여러 변경안을 묶는 경우에도
모두 같은 기준안에서 각각 만들며, 앞 변경안에 다음 변경을 누적하지 않는다.
2번의 `create_what_if_profile`은 변경안 하나를 생성한다. 3번의 배치 비교는 고유한
ASCII 식별자를 가진 `WhatIfScenario` list/tuple을 1~10개 받는다. 식별자 문법과
임시 자원 상한은 비교 계산 가이드에 정의한다.
이 규칙으로 무제한 배치나 서비스 응답 시간을 보장하지 않는다.

## 2. 변경 가능한 입력

변경 조건은 **변경 후 절대값**이다. 증감액·증감률·자연어 명령·금액 문자열은 받지 않는다.
한 변경안에 아래 조건을 하나 또는 여러 개 함께 지정할 수 있다.

| 조건 | 변경값과 적용 의미 | 미지정 시 |
|---|---|---|
| `monthly_savings` | 0 이상 원 단위 정수인 월 적립 **총액**. 현재 나이부터 변경된 은퇴 나이 직전 연도까지 적용 | 기준값 유지 |
| `retirement_age` | 18~100 정수이며 종료 나이 이하. 해당 연도부터 적립 중단·은퇴 생활비 적용. 아래 과거 변경 제한도 적용 | 기준값 유지 |
| `retirement_expenses` | `RetirementExpensePeriod`의 list/tuple로 **전체 생활비 일정 교체**. 항목 합계가 반영된 현재가치 월 총액 | 기준 일정 유지 |

예를 들어 기준 월 적립액 500,000원에 변경값 700,000원을 지정하면 총 700,000원을
적립한다. 1,200,000원으로 합산하지 않는다. 원래 적립액이 얼마든 명시적 `0`은
적립 중단이며 미지정이 아니다. 변경 시작 연도별 적립 일정은 이번 MVP에 없다.

현재 나이·종료 나이·기초 금융자산·연금 목록은 고정한다. 연금의 시작·종료 나이와
명목 월 수령액도 은퇴 나이에 맞춰 자동 이동시키지 않는다. 수익률 평균·변동성·물가·
경로 수·시드는 비교 전체에 하나만 사용한다. 미지원 필드는 조용히 무시하지 않는다.

### 미지정·0·빈 일정·검증

- 내부 변경 모델에서 선택 필드의 생략 또는 `None`은 **변경하지 않음**으로 정의한다.
  이는 변경 조건에만 적용하며 기존 `RetirementProfile`의 필수값에 `None`을 허용하는
  변경이 아니다. 외부 JSON `null`의 의미도 아직 정한 것이 아니다.
- `0`은 실제 변경값이다. `value or original` 같은 truthiness 대체를 사용하지 않는다.
- 생활비 빈 list/tuple은 일정 삭제 요청이다. 현재 모델은 최소 한 은퇴 연도가 있어야
  하므로 보장 구간이 없어 검증 오류다. 생활비 0원은 해당 나이를 덮는 금액 0 구간으로 쓴다.
- 금액·나이의 bool, 문자열, 소수 금액, 음수 금액은 기존 검증처럼 거부한다.
  생활비 dict·generator를 임의로 구간 모델로 변환하지 않는다.
- 아무 변경도 없는 조건과 기준값을 다시 지정한 조건을 허용한다. 새 불변 프로필을
  만들되 기준안과 입력값이 같아야 하며, 공통 경로의 금융 결과와 모든 차이는 각각
  동일·0이어야 한다. 계산 효과가 없는 정상 조건도 오류나 개선 결과로 꾸미지 않는다.

### 은퇴 나이의 과거 변경 제한

이 MVP는 현재부터의 계획 비교다. 과거 자산을 다시 계산하거나 재취업을 추정하지 않는다.

- 기준 `retirement_age >= current_age`이면 변경 은퇴 나이는 현재 나이 이상이어야 한다.
  현재 나이와 같으면 첫 계산 연도부터 은퇴한 것으로 계산한다.
- 기준 `retirement_age < current_age`인 이미 은퇴한 입력은 계속 허용하되 은퇴 나이를
  다른 값으로 변경하는 요청은 거부한다. 미지정·원래 값의 재지정은 허용한다.
  생활비 변경은 가능하고, 월 적립액만 바꿔도 은퇴 후 적립은 0이므로 결과는 같다.
- 이 제한은 **What-if 변경 검증**에만 둔다. 기존 모델·현금흐름 엔진의 이미
  은퇴한 입력 지원을 축소하지 않는다. 과거 재계산·재취업 시나리오는 후속 범위다.

## 3. 생활비 구간과 원본 보존

적용 순서는 `기준값 복사 → 지정된 변경값을 한꺼번에 적용 → 새 RetirementProfile 검증`이다.
은퇴 나이만 먼저 검증해 실패시키거나, 원본 객체의 필드를 수정했다 되돌리지 않는다.
새 모델은 frozen 구조이고 list 입력은 tuple로 복사해 호출자의 후속 수정과 분리한다.

1. 생활비를 지정하면 기존 구간과 부분 병합하지 않고 전체 일정을 대체한다. 특정
   구간만 바꾸려면 유지할 구간까지 포함한 완전한 일정을 명시한다.
2. 각 구간 양 끝을 포함한다. 시작·종료는 1~120, 시작은 종료 이하, 월 총액은
   0 이상 정수다. 나이순으로 정렬하며 **비활성 구간을 포함해** 중첩을 거부한다.
3. 변경 후 `max(current_age, retirement_age)..end_age`의 모든 나이가 정확히 한
   구간에 들어가야 한다. 누락은 0원·마지막 금액·옆 구간 금액으로 채우지 않는다.
4. 조기 은퇴로 새 연도가 필요하면 호출자가 확장된 전체 생활비 일정을 함께 제공한다.
   기존 일정이 이미 새 연도까지 포함하면 은퇴 나이만 변경해도 된다.
5. 은퇴를 늦추면 은퇴 전으로 바뀐 생활비 구간은 계산에 사용하지 않지만 입력에서
   자동 삭제·이동하지 않는다. 종료 나이 밖의 유효한 비중복 구간도 기존 모델처럼 보존한다.
6. 월 생활비는 두 안 모두 **같은 현재 나이 시점의 구매력 기준**이다. 물가 누적 지수는
   여전히 `age - current_age`이며 은퇴 나이나 구간 시작 나이에서 0으로 다시 시작하지 않는다.

금융자산·연금·시장 가정은 그대로 유지한다. 구간 객체가 불변이므로 내부 참조 공유는
허용하지만 가변 list나 원본 프로필을 제자리 수정하는 방식은 허용하지 않는다.

## 4. 공통 시장 경로와 기존 엔진 재사용

```text
기준안·변경 조건 검증 → 변경안 생성·생활비 재검증
  → 공통 N × T 수익률 경로 한 번 생성(또는 명시적 경로 전체 검증)
  → 기준안 계산·집계 / 같은 경로로 변경안 계산·집계
  → 기준 대비 차이 검증 → 불변 비교 결과
```

- `T = end_age - current_age + 1`이며 현재·종료 나이를 모두 포함한다.
  모든 안에서 `paths[k][t]`는 동일한 경로 `k`, 동일한 나이 `current_age + t`의 수익률이다.
- [`generate_return_paths`](../return_paths.py)를 비교 실행당 한 번만 호출한다.
  각 안에서 같은 시드로 다시 생성하는 방식에 의존하지 않는다. 은퇴 나이·고갈 여부로
  기간을 자르거나 수익률을 건너뛰거나 실패 경로를 버리지 않는다.
- 기준안과 변경안 모두 [`calculate_monte_carlo_paths`](../monte_carlo.py)에 동일한
  불변 경로 값과 공통 가정을 전달한다. 내부 검증용 복사본 생성은 허용한다.
  기존 현금흐름 순서·최초 고갈·전체 표본 분위수 규칙을 그대로 사용한다.
- 직접 경로를 받는 검산 입구도 둔다. 기존 list/tuple·정확한 `N × T` 크기·유한한
  수익률 `r > -1` 계약을 따르고 **전체 배치 검증 후** 첫 계산을 시작한다. 난수는 생성하지 않는다.
- 변동성 0은 고정 수익률 경로이며 RNG를 사용하지 않는다. 같은 조건의 반복 실행은
  같은 코드·Python 버전·환경에서 재현돼야 한다. 서로 다른 환경의 비트 단위 일치는 약속하지 않는다.
- 복수 변경안을 지원할 때에도 입력 전체를 먼저 검증하고 공통 경로와 기준 집계를
  한 번만 만든다. 변경안 순서로 금융 결과나 난수 소비가 달라지면 안 된다.

별도 실행에서 가져온 두 `MonteCarloResult`의 메타데이터가 같다는 이유만으로
공통 경로라고 간주하지 않는다. 비교 계산기가 실제 경로 재사용을 책임진다.
전체 원장·수익률 경로를 결과에 저장하거나 자동 로깅하지 않는다. 대량 경로 성능,
배치 상한의 적정성·timeout·취소·병렬화는 후속 검증 대상이며 임의로 `N`을 줄이지 않는다.

## 5. 비교 결과·차이의 단위

차이 방향은 항상 **변경안 − 기준안**이다. 각 안의 `MonteCarloResult`를 보존하고
차이는 그 요약에서 파생한다. 기준안은 변경안별로 달라지지 않는다.

| 비교 항목 | 차이 정의 | 단위·주의점 |
|---|---|---|
| 성공·고갈 확률 | `(changed_probability - baseline_probability) × 100` | 퍼센트포인트(pp), 범위 -100~100. 상대 증감률 아님 |
| 성공·고갈·미고갈 개수 | 변경 개수 − 기준 개수 | 부호 있는 정수. 동일한 전체 `N`을 분모로 사용 |
| 나이별 잔액 P10·P50·P90 | 같은 나이·같은 분위수끼리 변경 금액 − 기준 금액 | 표시 전 명목 KRW, 음수 보존 |
| 최종 잔액 P10·P50·P90 | 마지막 나이의 잔액 분위수 차이 | 마지막 연도와 별도 계산해 불일치시키지 않음 |
| 최종 부족액 P10·P50·P90 | 각 안의 부족액 분위수끼리 변경 금액 − 기준 금액 | 명목 KRW. 음수면 해당 부족액 분위수 감소 |
| 최초 고갈 나이별 개수 | 같은 나이의 변경 개수 − 기준 개수 | 0개인 나이도 포함. 합은 전체 고갈 개수 차이 |

성공확률이 0.60에서 0.75로 바뀌면 **+15pp**다. 이를 +15% 또는 +25% 상대 개선으로
대체하지 않는다. 확률 원본은 기존처럼 0~1이다. 반올림은 표시 단계에서만 하고,
기준 확률이 0이어도 분모로 나누지 않으므로 같은 차이 공식을 사용한다.

분위수끼리의 차이는 **경로별 차이의 분위수가 아니다**. 예를 들어 같은 두 경로의
금액 표본이 기준 `[0, 100]`, 변경 `[40, 60]`이면 각각의 P10/P50/P90은
`[10, 50, 90]`, `[42, 50, 58]`이고 분위수끼리의 차이는 `[32, 0, -32]`다.
경로별 차이 `[40, -40]`의 분위수 `[-32, 0, 32]`와 다르다. 이는 차이 의미를
구분하기 위한 합성 금액 표본이며 특정 고객의 실행 결과가 아니다.

- 따라서 **분위수 차이에는 P10 차이 ≤ P50 차이 ≤ P90 차이 제약을 적용하지 않는다.**
  기존 `AmountPercentiles`를 차이 모델로 재사용하지 않는다. 고갈 개수 차이도 음수가
  가능하므로 기존 비음수 `FirstDepletionCount`에 넣지 않는다.
- 경로별 개선 확률·성공↔실패 전환 개수·차이의 신뢰구간·최적안 추천은 MVP 출력에 없다.
  기존 집계만으로 개별 경로의 대응 관계를 복원했다고 주장하지 않는다.
- 미고갈을 종료 나이나 0세로 대체하지 않고 개수로 따로 보존한다. 최초 고갈의
  평균 나이·평균 지연 연수는 계산하지 않는다.
- 각 안의 성공은 **계획 중 음수 연말 잔액이 한 번도 없음**이다. 최종 부족액 0,
  최종 잔액 양수여도 중간 고갈을 취소하지 않는다. 잔액 0 자체는 고갈이 아니다.
- 차이의 부호는 해당 지표만 설명한다. 모든 지표를 한 점수로 합치거나 기존 BE
  준비율과 동일시하지 않는다. 결과는 입력 가정·유한 표본에 따른 비교이지 보장이 아니다.

## 6. 실행 출처·오류 계약

What-if 규칙 식별자는 `retirement-what-if-v1`로 정한다. 비교 결과에는 공통 기간·
가정·경로 수와 실제 경로 생성/직접 지정 여부, What-if·몬테카를로 버전·Python 정보를
남긴다. `WhatIfResult.model_version`은 What-if 규칙, `.metadata`는 실제 공통 경로의
몬테카를로 메타데이터다. 세부 결과 필드는 비교 계산 가이드에 정의한다.

| 실제 공통 경로 출처 | 비교 전체의 출처 정보 | 각 하위 몬테카를로 결과 |
|---|---|---|
| 내부 생성, 변동성 양수 | 생성됨, 로그정규 모델·실제 RNG·시드 | `provided`, 유효 RNG·시드는 `None` |
| 내부 생성, 변동성 0 | 생성됨, 고정 수익률 모델·RNG/유효 시드는 `None` | `provided`, 유효 RNG·시드는 `None` |
| 호출자가 직접 전달 | 직접 지정됨, 모델·RNG·유효 시드는 `None` | `provided`, 유효 RNG·시드는 `None` |

하위 결과는 실제로 `calculate_monte_carlo_paths`를 호출하므로 `provided`가 맞다.
그 메타데이터를 사후 수정해 생성 실행으로 꾸미지 않는다. 비교 계층에서 실제로
생성한 출처만 별도로 기록한다. 설정됐지만 쓰이지 않은 값은 공통 가정에 남으며,
직접 경로의 재현에는 원래 경로 값이 필요하다. 시드만으로 생성 출처를 추정하지 않는다.

- 입력 검증은 기존 `ModelValidationError`를 사용한다. 필수 생성 인자 누락 등
  Python 호출 규격 오류는 `TypeError`다. 원본 프로필 검증 규칙을 우회하지 않는다.
- 시나리오 검증 실패 시 난수 생성·기준안 계산도 시작하지 않는다. 수익률 생성·
  현금흐름·집계 오류와 차이 계산의 비유한 값은 **비교 전체 실행 오류**다.
  한쪽 결과만 반환하거나 오류를 고갈 1건·차이 0으로 바꾸지 않는다.
- 양쪽 요약이 각각 유한해도 뺄셈이 overflow할 수 있으므로 차이도 유한성 검증한다.
  값 자르기·재추출·실패 경로 제외·분모 변경으로 보정하지 않는다.
- `WhatIfCalculationError`는 발생 단계, 공통 시장/기준/변경안 구분 및 가능한
  변경안·경로 인덱스·나이·필드명을 보존한다. 금액·원본 조건·전체 경로·
  자유 입력 라벨을 오류 메시지나 기본 `repr`에 노출하지 않는다.

## 7. 손계산 기대값

### A. 월 적립 총액 변경·변경 없음

현재 58세·은퇴 60세·종료 61세, 기초 금융자산 1,200원, 월 적립 100원,
60~61세 월 생활비 100원, 61세에만 월 연금 50원이다.
가정은 평균·변동성·물가 모두 0, `N=3`, 시드 7이다. 생성된 모든 수익률은 0이다.
변경안은 **월 적립 총액 200원**이고 다른 입력은 그대로다.

| 나이 | 기준안 연말 잔액 | 변경안 연말 잔액 | 차이 |
|---|---:|---:|---:|
| 58 | 2,400 | 3,600 | +1,200 |
| 59 | 3,600 | 6,000 | +2,400 |
| 60 | 2,400 | 4,800 | +2,400 |
| 61 | 1,800 | 4,200 | +2,400 |

각 나이의 세 분위수는 해당 잔액과 같다. 둘 다 성공 3개·성공확률 1, 확률 차이
0pp, 최종 부족액과 그 차이는 모두 0이다. 은퇴하는 60세에는 변경 적립액도 들어가지 않는다.
변경 없음 또는 적립 총액 100원 재지정은 기준안과 결과가 같고 모든 차이가 0이다.

### B. 조기 은퇴와 구간 누락·은퇴 연기

A의 기준안에서 은퇴를 59세로만 바꾸면 59세 생활비가 없어 **입력 오류**다.
은퇴 59세와 **59~61세 월 생활비 100원의 전체 일정**을 함께 지정하면 다음과 같다.

| 나이 | 기준안 잔액 | 조기 은퇴안 잔액 | 차이 |
|---|---:|---:|---:|
| 58 | 2,400 | 2,400 | 0 |
| 59 | 3,600 | 1,200 | -2,400 |
| 60 | 2,400 | 0 | -2,400 |
| 61 | 1,800 | -600 | -2,400 |

연금은 여전히 61세에만 연 600원이다. 조기 은퇴안은 60세 잔액 0에서는 고갈하지
않고 61세에 3개 모두 처음 고갈한다. 성공확률 차이는 -100pp, 최종 부족액 분위수는
모두 600원, 기준 대비 부족액 차이는 모두 +600원이다.

반대로 A에서 은퇴만 61세로 늦추면 기존 생활비 일정을 보존한 채 60세까지 적립한다.
연말 잔액은 `[2,400, 3,600, 4,800, 4,200]`, 기준 대비 차이는
`[0, 0, +2,400, +2,400]`이다. 60세 생활비를 61세로 이월·합산하지 않는다.
연금은 은퇴 변경과 무관하게 원래 일정대로 적용된다.

### C. 생활비 변경·고갈 후 회복·pp 비교

현재·은퇴 60세·종료 61세, 기초 금융자산 120원, 적립 0원, 61세에만 월 연금
20원이다. 생활비는 기준 60~61세 월 10원, 변경은 같은 전체 구간 월 5원이다.
가정은 평균 0.05·변동성 0.10·물가 0, `N=4`, 시드 42로 명시하되 아래 **수동
경로가 평균·변동성·시드를 대신**한다. 난수 추출 결과라고 표시하지 않는다.

| 경로 | 60·61세 수익률 | 기준 잔액 60·61세 | 변경 잔액 60·61세 |
|---|---|---|---|
| 0 | `(-0.5, 0)` | `(-60, 60)` | `(0, 180)` |
| 1 | `(0, 0)` | `(0, 120)` | `(60, 240)` |
| 2 | `(0.5, 0)` | `(60, 180)` | `(120, 300)` |
| 3 | `(1.0, 0)` | `(120, 240)` | `(180, 360)` |

| 집계 | 기준 | 변경 | 차이 |
|---|---|---|---|
| 성공 개수·확률 | 3개·0.75 | 4개·1.0 | +1개·+25pp |
| 최초 고갈 개수(60·61세) | `(1, 0)` | `(0, 0)` | `(-1, 0)` |
| 60세 잔액 P10/P50/P90 | `(-42, 30, 102)` | `(18, 90, 162)` | `(60, 60, 60)` |
| 최종 잔액 P10/P50/P90 | `(78, 150, 222)` | `(198, 270, 342)` | `(120, 120, 120)` |
| 최종 부족액 P10/P50/P90 | `(0, 0, 0)` | `(0, 0, 0)` | `(0, 0, 0)` |

기준 경로 0은 마지막에 회복해도 중간 고갈 때문에 실패다. 양쪽 최종 부족액이
전부 0이라고 성공확률 차이를 0pp로 만들면 안 된다.

## 8. 단계별 구현·검증 기준

1번에서 아래 규칙을 문서화했고 5번 전용 샘플까지 완료했다.
권장 커밋 구성은 [README](../README.md)에 있다.

| 2번 시나리오 생성(완료) | 변경값 절대값·0/미지정 구분, 전체 일정 교체, 동시 변경 후 검증, 원본 불변, 은퇴 전후·과거 변경 제한·미지원 입력 |

물가 0이 아닌 경우의 현재 나이 기준 누적, 음수·순서가 뒤집힌 분위수 차이,
확률 기준값 0, 직접 경로 전체 선검증, 비교 도중 오류 시 부분 결과 금지도 테스트한다.
후속 테스트는 What-if 공개 입구를 호출해야 한다. 기존 엔진을 수동 조합한 검산만으로
시나리오 생성기나 비교 계산기가 검증됐다고 기록하지 않는다.

### 1번 문서 작성 시점의 검증 기록

2026-09-08, Miniforge `retirewise-ai`의 Python 3.13.15에서 기존 전용 테스트
**181개 통과**를 확인했다. 일반 실행과 `-S` 실행(추가 site-packages 없이 실행)을
각각 확인했다. 아래 명령은 저장소 루트 기준이다.

```bash
conda run -n retirewise-ai python -B -m unittest discover -s ai-pjt/retirement_simulation/tests -q
conda run -n retirewise-ai python -S -B -m unittest discover -s ai-pjt/retirement_simulation/tests -q
```

A~C의 입력을 기존 모델로 직접 구성하고 기존 현금흐름·몬테카를로 엔진에 같은
경로를 전달해 손계산 기대값과 대조했다. 조기 은퇴의 누락 구간 거부·명시적 구간
추가 허용, 원본 불변·변경 없음·적립 0·생활비 빈 일정과 0원의 차이·물가 누적
기준·직접 경로 출처도 일회성으로 점검했다. 5절의 분위수 차이 예시는 별도
표준 라이브러리 `statistics.quantiles(method="inclusive")`와 대조했다.
이는 명세의 기존 계약 호환성 검산이며 **신규 What-if 자동 테스트 수에 포함하지 않는다**.
전용 모델·비교 계산기·샘플·성능·서비스 연결 검증은 후속 작업이다.

### 3번 비교 계산

### 5번 합성 비교 샘플

`retirement_simulation.what_if_samples`에 기존 합성 프로필 3종·명시적 변경안 11개의 실제 비교

기존 고정/몬테카를로 CLI는 미구현 안내만 새 명령으로 갱신했다. 실행·출력·검증 범위는
