# 비모델링 금융자산 입력 보완 — 0.1.2

작성일: 2026-09-11. 기준: `master=c4b0327`.
브랜치: `fix/ai-simulation-unmodeled-assets`.
현재 단계: **0~3번 모듈 작업 완료. BE 테스트 기대값 조정·원격 MR·서비스 적용은 별도 후속 작업.**

## 1. 변경 이유와 작업 범위

[금융자산 폼](../../../front-pjt/src/components/forms/FinancialAssetsForm.vue)의 `기타`는
[공통 테이블](../../../front-pjt/src/components/ui/AddableTable.vue)에서 빈 값과 직접 입력 칸으로
전환된다. [저장 모델](../../../backend-pjt/consulting/models.py)의 `asset_type`도 nullable 문자열이며
고정 선택지 enum이 아니다. 따라서 `기타`만 제외하는 0.1.1 규칙으로는 `전세보증금` 같은
정상적인 직접 입력이 `unsupported_value`로 전체 분석을 실패시킨다.

이번 수정은 **분류를 추측하지 않고, 모델링하는 5종 이외의 유효 문자열 행을 제외**하는 것이다.
계산식·수익률 가정·공개 함수·JSON 구조·notice 코드·모델/매핑 버전은 유지하고 패키지는
`0.1.2`로 구분한다. 기존 0.1.1에서는 오류였던 입력이 부분 분석 성공으로 바뀌므로
호출자는 패키지 버전과 반영 범위 안내를 함께 고려해야 한다.

변경은 `ai-pjt/retirement_simulation/` 내부의 어댑터·테스트·문서·패키지 버전에 한정한다.
BE·FE·Agent·공통 정책·CI·Docker·의존성은 변경하지 않는다. 푸시·MR·병합·배포·담당자 메시지
전송은 이 0~3번 작업에 포함하지 않는다.

## 2. 확정 입력 규칙

[기존 `_text_field`](../input_adapter.py)로 필수 텍스트를 읽고 양 끝 공백만 제거해 비교한다.

| `asset_type` 입력 | 처리 |
|---|---|
| `예금/적금`, `주식`, `펀드/ETF`, `채권`, `가상자산` | 기존대로 평가액·월 적립액 검증 및 합산 |
| `기타`, `전세보증금`, `보험 해약환급금`, `회원권` 등 그 외 비어 있지 않은 문자열 | 행 전체를 자산·적립 합계에서 제외하고 notice 생성 |
| `예금적금`, `기 타` 등 오타/변형 문자열 | 추정·보정 없이 위 제외 규칙 적용 |
| 키 누락 | `missing_field`, `financial_assets[N].asset_type` |
| `null`, 빈 문자열, 공백만 있는 문자열 | `missing_value`, 같은 필드 경로 |
| 숫자·bool·배열·객체 등 비문자열 | `invalid_type`, 같은 필드 경로 |

문자열 `asset_type`의 `unsupported_value` 분기는 사라지지만 연금 수령방식·기간·목표 phase
등 다른 필드의 `unsupported_value` 검증은 유지한다. 임의 문자열을 `기타`로 치환하거나
상품명·금액·키워드에서 분류를 추측하지 않는다. 입력 dict/list·문자열·금액은 수정하지 않는다.

### 합산·안내·검증 경계

- 제외 행의 `current_value`와 `monthly_savings`를 모두 합산하지 않는다. 누락·null을 0으로
  채우는 것이 아니라 사용하지 않는 금액 필드를 읽거나 검증하지 않는 기존 제외 패턴을 따른다.
- 제외 행에도 mapping 구조·필수 분류 텍스트·있으면 양의 정수인 ID·중복 ID 검증은 유지한다.
  다른 모델링 행의 금액 오류나 다른 섹션의 필수 오류는 계속 전체 분석 실패다.
- 제외 행마다 `other_financial_asset_not_modeled`와 `field_name="financial_assets[N]"`를 남긴다.
  `N`은 원본 배열의 0 기반 위치이며 DB ID나 필터 후 위치가 아니다. 사용자 입력 원문은 담지 않는다.
- 모든 행이 제외되면 자산·월 적립 합계는 0이지만 실제 빈 목록이 아니다.
  `confirmed_empty_financial_assets`를 만들지 않고 없음 확인을 강제로 추가하지 않는다.
  비어 있지 않은 목록의 없음 확인은 기존처럼 `invalid_confirmation`이다.
- 기준 몬테카를로와 What-if 모두 같은 매핑과 notice를 사용한다. What-if의 `monthly_savings`는
  변경 후 총 월액이며 제외된 행의 금액을 재합산하지 않는다. 새 안내 코드는 추가하지 않는다.

## 3. BE·화면 연결 시 주의사항

모듈의 부분 분석 지원과 서비스의 실행 허용 조건은 서로 다르다.
BE의 임시 분류 차단은 **사용자가 화면에서 제외 사실을 확인할 수 있을 때까지 유지**한다.
패키지 설치나 notice의 JSON 보존만으로 차단 제거·서비스 연결 완료를 선언하지 않는다.

기준 master의 [BE 어댑터 테스트](../../../backend-pjt/tests/test_simulation_adapter.py)에 있는
`test_every_rejected_case_is_also_rejected_by_the_module`은 `free_text_asset_type` 사례의
`전세보증금`을 모듈도 거부해야 한다고 기대한다. 0.1.2에서는 모듈이 notice와 부분 분석을
반환하므로 이 기대값과 충돌한다. BE 담당자가 다음처럼 구분해야 하며, 모듈 작업에서 BE 파일을
수정하거나 테스트를 비활성화하지 않는다.

- 영구적인 입력 오류: BE와 모듈 모두 거절하는 검증 유지.
- 화면 안내 전 임시 차단: BE는 차단하되 모듈은 제외 안내와 부분 분석을 반환하는 별도 검증.

실제 차단 제거 시 [BE 어댑터](../../../backend-pjt/simulations/adapter.py)의 **계산용 금액 사전 검사**도
제외 행의 미사용 금액을 다시 오류로 만들지 않는지 확인한다. 이는 저장 serializer의 금액 유효성
검사를 없애라는 뜻이 아니다. 사용자 안내·차단 해제·BE 테스트 조정은 BE/화면 담당 범위다.

## 4. 작업 순서와 검증 기준

| 단계 | 범위 | 완료 기준 |
|---|---|---|
| 0 | 최신 master·작업 트리 확인, 새 브랜치 | 이전 브랜치가 master에 포함되고 미커밋 변경 없음 확인 |
| 1 | 이 문서로 규칙·호출자 영향 확정 | 코드 원천/링크 확인, 기준 회귀, 문서 커밋 |
| 2 | 어댑터·소스/설치 회귀·현재 입력 가이드 수정 | 변경 전 실패 재현, 변경 후 전체 소스 및 `-S` 회귀 통과 |
| 3 | 0.1.2 버전·설치 문서·빌드/설치 검증 | sdist→wheel, 버전/파일/해시 확인, 격리 설치 검사, BE 호환성 결과 기록 |

혼합·모두 제외·다중 제외·원본 index·오타·공백·null·자료형·필드 누락·행/ID·다른 행의 오류·
미사용 금액·원본 불변을 검증한다. 양수 변동성과 고정 seed의 MC/What-if에서 제외 행을 추가하기
전후 notice 이외의 응답이 같은지도 대조한다. 테스트 메서드 수와 내부 입력 조합 수는 구분한다.
단계별 검증 후 Conventional Commit 접두사와 한국어 설명으로 로컬 커밋한다.

실제 고객 데이터·Django HTTP·Docker·운영 배포/E2E 성공은 이 합성 모듈 검증의 범위가 아니다.
검증 결과는 구현 후 [입력 검증 기록](input-adapter-validation.md)과
[설치 검증 기록](installation-validation.md)에 추가하며 과거 버전의 기록은 보존한다.

### 0·1번 확인 기록

- 이전 0.1.1 수정 커밋 `d503d65`가 최신 master에 포함됨을 확인했다. 깨끗한 로컬 master를
  `c4b0327`로 fast-forward한 뒤 새 브랜치를 생성했다. rebase·병합 커밋·기존 브랜치 삭제는 없다.
- Miniforge `retirewise-ai` / CPython 3.13.15에서 기존 소스 **682개**가 일반·`-S` 실행 모두 통과했다.
- 이 문서의 로컬 링크 **8개**와 `git diff --check`를 확인했다. 1번 변경은 이 문서 하나뿐이다.

### 2·3번 확인 기록

- 소스 회귀 **685개**, 별도 wheel 격리 설치 **18개**를 통과했다. 상세 실행/빌드/파일 검사는
  [입력 검증 기록](input-adapter-validation.md)과 [설치 검증 기록](installation-validation.md)에 남겼다.
- BE 패키지·어댑터 검사는 **45개 중 44개 통과, 자유 입력의 모듈 오류 기대값 1개 실패**다.
  테스트를 비활성화하거나 BE 차단을 제거하지 않았다. 따라서 전체 CI 통과나 병합 준비 완료는 아니다.
- 버전은 0.1.2지만 공개 Python 함수·JSON 구조·기존 notice 코드·모델/매핑 버전은 유지했다.
  각 단계의 로컬 커밋만 진행하며 푸시/MR/병합/배포는 사용자 요청 전 실행하지 않는다.
