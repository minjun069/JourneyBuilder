# BE 전달용: 시뮬레이션 설치·호출 확인서

갱신일: 2026-09-10. 코드 기준 MR !52 병합 후 `master=d39677b`.
2026-09-11에는 패키지 `0.1.2` 설치 검증·분류 규칙 변경과 BE 테스트 호환성 결과를 갱신했다.
**기능·모듈 측 기준 확정 / 기술 확인 항목 관리** 문서이며,
이 갱신으로 아래 항목 전체의 합의나 BE 설치 완료를 선언하지 않는다. BE/FE 파일은 수정하지 않았다.
현재 FE 담당자는 없다. 기능 담당과 BE가 설치/API 계약을 먼저 확인하고 화면 구현 담당·수정 범위는
별도로 확정한다. FE 구현 대기와 BE/API 연결 진행을 구분한다.
확인 대상은 몬테카를로·What-if 연결이며 Agent 라우팅·컨텍스트·매뉴얼 변경 요청이 아니다.

## 1. 현재 제공하는 것과 다음 제공물

- 완료: 저장형 입력/변경 매퍼, `analyze_retirement()`, 결과·오류 dict 변환, 합성 CLI·회귀 테스트.
- 완료: `retirewise-retirement-simulation==0.1.2` wheel/sdist·빌드 설정·격리 설치 검증 18개.
  import는 `retirement_simulation`이며 Python 3.13 계열, 런타임 외부 의존성은 없다.
  모델링 5종 밖의 자유 문자열·오타 제외와 필수 텍스트 오류 구분이 포함되며 기존 0.1.1 설치본과 구분한다.
  실제 BE 적용은 별도이며 [변경 안내](unmodeled-financial-assets.md)의 임시 차단/테스트 경계를 따른다.
- 후속 BE 확인 완료: MR !80 병합(`master=a2f8650`)으로 임시 차단/모듈 오류 테스트가 분리됐다.
  패키지·어댑터 **46개 전부 통과**, 기존 기대값 충돌은 해결됐다. 실제 차단은 화면에서 제외 안내가
  가능할 때까지 유지한다. 모듈 담당 브랜치에서 BE 파일이나 차단 로직을 수정하지 않았다.
- 완료: [MVP 정책](simulation-policy.md), [입력/출력 샘플](handoff-examples.json), [가정 검증](handoff-validation.md).
  기준+변경 1개, 변경 후 준비율 제외, 부분 분석 안내 유지, 4%/10%/2%·1,000경로·시드 42.
- 제안: 모듈 담당이 단일 소스 wheel과 버전/해시·설치 검증을 제공하고 BE에서 직접 import해 호출.
  정확한 이미지 포함 방식·담당자는 아래에서 확인한다. 공개 PyPI 게시나 별도 계산 서버는 제안하지 않는다.

호출/오류 예시는 [BE 인수인계](be-handoff.md), 정확한 Python 인자는
[통합 호출 규격](analysis-contract.md)에 있다. Python 규격을 HTTP API 계약으로 확정했다는 뜻은 아니다.

## 2. BE에서 재사용할 수 있는 코드

| 현재 코드 | 확인한 사실 | 아직 확인할 점 |
|---|---|---|
| [Compose](../../../docker-compose.yml)·[BE Dockerfile](../../../backend-pjt/Dockerfile) | 루트 build context, Python 3.13.14. 기존 requirements는 해시 검증 설치. 모듈 설치 단계 없음 | wheel을 어디서 빌드/보관/설치할지, 설치 권한·버전 잠금·담당자 |
| [보고서 스냅샷](../../../backend-pjt/reports/snapshots.py) | 저장 관계를 모으는 helper와 입력 digest 함수 있음 | 모듈 입력 타입/null·동일 시점 읽기·없음 확인의 근거 |
| [공통 정책](../../../contract-fixtures/financial-calculation/v1/policy.json)·[로더](../../../backend-pjt/reports/policy.py) | 기본 수익률 4%·물가 2%·정책 버전은 있으나 MC 변동성 없음. 전용 [MVP 정책](simulation-policy.md)은 별도 확정 | 기존 공통 정책을 변경하지 않고 전용 설정/정책 버전을 배치·검증·응답하는 방법 |
| [보고서 서비스](../../../backend-pjt/reports/services.py) | required_savings 결과에 정책 버전·입력 digest 기록 | 시뮬레이션 기준과 연결할 식별/만료·실제 준비율 원천 |

스냅샷 조회와 digest 계산을 각각 호출하면 조회 시점이 달라질 수 있다. 함수가 이미 있다고
동일 기준을 보장한다고 간주하지 않는다. 샘플의 없음 확인·가정을 실제 고객에게 복사하지 않는다.

## 3. 확인받을 항목

아래는 **연결을 위한 기술 확인 질문**이다. 이미 확정한 기능/가정을 다시 선택해 달라는 문서가 아니다.
Q1~Q6은 BE 연결 전에 확인하고, Q7의 실제 준비율 원천/응답 필드도 BE와 먼저 확인한다.
Q5/Q7의 화면 표시·구현 책임은 화면 담당 확정 후 보완한다. 역할·URL·배포 권한은
작성자 단독으로 확정하지 않으며 기존 합의가 있다면 그 근거를 기록한다.

| ID | 질문 | 모듈 측 제안·주의 |
|---|---|---|
| Q1 | BE 이미지 설치와 계산 API 연결은 누가 맡으며, 내부 wheel 설치 방식으로 진행 가능한가? | 소스 복제/임시 sys.path 없이 설치. BE Dockerfile·의존성 잠금 변경은 별도 담당/승인 범위 |
| Q2 | 어떤 상담 상태·동일 시점 입력을 기준으로 계산하고, 금융자산/연금이 실제로 없다는 사실은 어떻게 확인하는가? | 기존 snapshot helper 재사용 검토. 빈 목록·완료 플래그만으로 없음 확인을 자동 부여하지 않음 |
| Q3 | 전용 정책을 어디에 배치하고 로딩·버전 기록·설정 오류를 어떻게 처리하는가? | [정책 JSON](simulation-policy.json)의 다섯 값만 함수에 전달. metadata는 응답 envelope에 기록. wheel에는 정책 JSON이 없으며 자동 기본값/공통 정책 변경 금지 |
| Q4 | 계산 URL·요청/응답·오류 상태·인증/소유권·기준 ID/만료는 어떻게 정하는가? | 브라우저는 실행 의도/가상 변경을 전달. BE가 원천을 조회. 기존 완료 상담 제한이 있는 채팅 API를 그대로 재사용하지 않음 |
| Q5 | 확정한 부분 분석 안내를 어떤 응답 필드/FE 표시로 연결하는가? | 부분 분석 허용 및 짧은 안내+계산 기준은 확정. 모든 notices 보존, 원천 목록 삭제/성공확률만 전달 금지 |
| Q6 | 실제 BE에서 허용 기간·동시 실행·시간 제한·취소·중복/재시도 정책은 무엇인가? | MVP 1,000경로·변경 1개. 51년은 기존 시험 사례이지 기간 상한이 아님. 다중 worker 제한/timeout 시 계산 회수 확인 |
| Q7 | 기존 준비율의 실데이터 원천은 무엇이고, 어떤 화면/필드로 연결하는가? | 변경 후 준비율 제외 확정. 고정값 28%/67% 재사용 금지. [FE 안내](fe-handoff.md)의 세 조건·전체 일정·단위·오래된 응답 처리 확인 |

기존 입력의 `monthly_savings`는 월 적립 총액이다. What-if에서 0은 유효한 변경이고,
생략/null은 유지다. 생활비는 전체 일정 교체이므로 조기 은퇴 기간도 채워야 한다.
모듈은 비교 결과를 만들 뿐 원본 고객 정보·보고서·AI 컨텍스트를 저장/수정하지 않는다.

## 4. 확인 전후의 작업 경계

- **모듈 측 완료:** 패키징·격리 설치·확정 가정/조합 테스트·민감도/시드 진단·BE/FE 전달 문서.
- **확인과 변경 권한이 필요한 작업:** BE 이미지·API·가정 설정·조회 연결, 공통 정책 수정,
  FE 버튼/조건 입력·차트·준비율 연결, 공용 CI·배포 변경.
- **이번 연결에 불필요:** 다른 AI 담당의 Agent 라우팅·컨텍스트·재무상담 매뉴얼 재구현.

정식 회의가 필수인 것은 아니다. 이 문서에 대한 답변이나 기존 계약 확인으로 진행할 수 있다.
문서 작성/전달 또는 무응답을 합의로 해석하지 않는다. 미확정 사항이 남으면 모듈 인수와 서비스 인수를
구분하고, 다른 담당 영역을 임의 변경하지 않는다.
